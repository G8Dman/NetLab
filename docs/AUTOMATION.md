# NetLab Automation 0.4.4-alpha

Minecraft 1.21.1 / NeoForge 21.1.265. Нужны оба JAR на клиенте и сервере:

- build/libs/netlab-0.14.2-alpha.jar
- build/libs/netlab-automation-0.4.4-alpha.jar

Пакеты предметов и их время доставки: [ITEM-PACKETS.md](ITEM-PACKETS.md).

## Питание и портативный доступ

С NetLab 0.12 сервер, коммутатор и мультиинтерфейсы требуют FE. Схема:
источник FE → энергошкаф → блок питания в отдельном месте шкафа → отдельные
кабели к задним входам плат. Обе ячейки шкафа остаются для устройств.
Старые стенды нужно запитать вручную; новый demo automation включает тестовый
источник и всё питание автоматически. В выживании используется совместимый
источник FE другого мода. Подробности: [POWER-AND-PORTABLE.md](POWER-AND-PORTABLE.md).

Портативный терминал открывает ту же Console по ПКМ разъёма без компьютера.
Пароли и права владельца сохраняются. Истории после закрытия у него нет.

## Готовый стенд и место ввода команд

В чате Minecraft введи /netlab demo automation. Нужны права оператора уровня 2
и свободная область 11×7×3 к югу (+Z). Все блоки области проверяются до начала
строительства; существующие блоки не заменяются. Демо выбирает свободную /24
среди загруженных устройств, начиная с 192.168.77.0/24.

Появятся два сундука, два мультиинтерфейса, шкаф с сервером внизу и коммутатором
вверху, три ноутбука с USB-RS232 и готовыми кабелями Console, таблички и свет.
В источнике 64 железных слитка; получатель пустой. Адреса, server-address, разрешения и питание FE готовы. Автоперенос пока выключен — запускается командами из книги.

Выдаётся обычная написанная книга «Автоматика: первый перенос» с настоящими
IP стенда. Нажатие на зелёный фрагмент команды копирует всю команду, включая
длинную transfer. Текст разбивается на страницы; при полном инвентаре книга
выпадает рядом.

**inspect и transfer вводятся на сервере управления.** Открой центральный
ноутбук с табличкой SERVER → Desktop → Terminal. Его Console уже соединён с
Console сервера. Введи enable; если находишься в config, сначала end.
На приглашении DEMO-SERVER# выполняй inspect/transfer. В чат Minecraft или
терминал мультиинтерфейса эти команды не вводятся.

Боковые ноутбуки SOURCE и DESTINATION открывают Console своих
мультиинтерфейсов. Там настраивают IP, target, server-address и разрешения.

**Шлюз в этом демо не нужен:** сервер и интерфейсы в одной /24 и VLAN 1.
Шлюз нужен при обращении к другой подсети; это LAN-IP настоящего маршрутизатора,
а не IP сервера. Одинаковые адреса подсети в разных изолированных VLAN не
создают связь — нужны согласованные VLAN/маршрутизация и обратный путь.

## Устройства и доступ

Сервер управления — плоское устройство высотой 4/16 блока. Можно установить
в любую из двух ячеек шкафа обычным ПКМ предметом по выбранной половине или
поставить отдельно. У сервера и мультиинтерфейса есть GigabitEthernet0/0 и Console.
Console подключается к RS232 ПК/ноутбука; ноутбуку сначала нужен USB-RS232.

ПКМ по серверу/мультиинтерфейсу открывает физическую панель: питание, порты,
индикация связи и счётчики. Настройка приложения выполняется через Desktop →
Terminal подключённого компьютера. Старые GUI-запросы настройки для этих блоков
отклоняются. Анализатор сохраняет отдельное окно просмотра перехваченных кадров.

Доступ к приложению, изменения физической панели и снятие сервера проверяют
владельца. Новое устройство принадлежит установившему его игроку. Сервер и его
мультиинтерфейсы должны иметь одного владельца. Это права Minecraft, а не
полноценная AAA/учётная запись Cisco IOS.

## Шкаф и отвёртка

Предмет «Отвёртка» находится во вкладке NetLab. Рецепт: железный слиток, красный
краситель, палка вертикально. Shift+ПКМ по верхней/нижней половине шкафа снимает
только выбранное устройство. Поддерживаются роутер, коммутатор, контроллер
трафика и сервер автоматики. Его кабели отсоединяются, вторая ячейка сохраняется.

Возвращается предмет с Device-конфигурацией, установленными аппаратными модулями
и состоянием приложения сервера: владелец, идентичность, правила, настройки.
Предмет можно снова установить в шкаф или отдельно. Заполненный предмет при
установке в шкаф расходуется и в creative, чтобы обычное переустановление не
клонировало идентичность. При разрушении шкафа установленные устройства
выпадают отдельно. Отвёртка не даёт доступа к чужому серверу.

VPN-секреты роутеров хранятся отдельно на сервере мира и привязаны к сетевому
идентификатору ячейки. После переноса роутера в другую позицию VPN-пару нужно
настроить заново. Секреты не переносятся через клиентский ItemStack.

Старые отдельно стоящие устройства сохраняют совместимость. При загрузке
добавляется Console; старые NBT-настройки переносятся в состояние приложения.
Журнал незавершённых передач остаётся в SavedData мира.

## Быстрая лаборатория

Сначала подключи питание всех сетевых устройств, дождись зелёного PWR.
Без FE даже правильно настроенные IP не создадут рабочую связь.

Сервер: 192.168.1.10/24; два мультиинтерфейса: .11 и .12. Подключи RJ45 всех
устройств к коммутатору. Под мультиинтерфейсами поставь сундуки. Если нужна
другая подсеть, настрой маршрутизатор, обратные маршруты и соответствующий шлюз.

Через Console сервера:

    enable
    configure terminal
    hostname SERVER
    interface gig0/0
    ip address 192.168.1.10 255.255.255.0
    no shutdown
    exit
    end

Через Console первого мультиинтерфейса:

    enable
    configure terminal
    hostname MI1
    interface gig0/0
    ip address 192.168.1.11 255.255.255.0
    no shutdown
    exit
    server-address 192.168.1.10
    target down
    permission extract on
    permission insert on
    end
    show automation

Для второго повтори с IP 192.168.1.12 и именем MI2. В этом примере шлюз оставь пустым. Для другой подсети задай в config
ip default-gateway IP_МАРШРУТИЗАТОРА. Мультиинтерфейс примерно раз в пять секунд отправляет серверу
REGISTER_STATUS по его IP и ожидает ACK. show endpoints на сервере показывает
доставленные отчёты и время получения, а не всеведущее состояние всех блоков.

В Console сервера через подключённый компьютер → Desktop → Terminal,
после enable (или end для выхода из config), на приглашении SERVER#:

    inspect 192.168.1.11
    transfer 192.168.1.11 192.168.1.12 minecraft:iron_ingot 16
    show jobs

Передача проверяет доступ к обоим интерфейсам по сети, извлекает предметы в
журнал, отправляет OFFER, затем через 20 секунд после доставки OFFER пытается
погасить билет. После ACCEPT источник отправляет ITEM_DATA получателю;
предметы вставляются только после прибытия этого пакета. Сетевая задержка добавляется ко всем этапам. Чтение/извлечение/
вставка и управление выполняются после соответствующей доставки сообщения.
Недоступность получателя оставляет остаток груза в журнале.

## Программирование правилами

В конфигурации сервера:

    automation rule 192.168.1.11 192.168.1.12 minecraft:iron_ingot 64 16
    automation run

Правило поддерживает запас 64 предмета, заказывая до 16 за раз. До 16 правил;
сервер проверяет их по очереди, когда свободен от сетевой операции. Пока груз к
получателю ожидает завершения, дополнительная передача к нему не создаётся.

    automation stop
    automation clear

Остановка и очистка правил не уничтожают уже принятые грузы. Это декларативная
программа логистики, не исполнение произвольного Java/Lua-кода.

## Команды приложения

help / ? выводит синтаксис приложения и базовые команды текущего режима.
Tab дополняет команды. Имена специальных команд приложения вводятся полностью;
для базовых IOS-подобных команд работают обычные однозначные сокращения.

Глобальная конфигурация мультиинтерфейса:

- server-address IP — доверенный сервер.
- target down|up|north|south|west|east — соседний блок; capability берётся с
  противоположной стороны его грани.
- permission extract|insert|control on|off — разрешения. Отключение control
  сбрасывает redstone в ноль.

Глобальная конфигурация сервера:

- automation rule SOURCE DESTINATION ITEM MINIMUM BATCH — правило запаса.
- automation run / stop / clear — запустить, остановить, удалить правила.
- vpn required|optional — требовать согласованный роутерный VPN для пути через
  два или более роутера. Это требование к доставке, не локальное шифрование.

Привилегированный EXEC сервера:

- inspect IP — прочитать состояние мультиинтерфейса.
- transfer SOURCE DESTINATION ITEM COUNT — передать 1..64 предмета.
- machine IP ACTION — выполнить разрешённое действие: signal 0..15, play, stop
  либо действие зарегистрированного адаптера.
- claim UUID DESTINATION — погасить билет.
- return UUID — вернуть груз источнику.

Диагностика EXEC:

- show automation — IP, шлюз, сервер, разрешения, направление и статус.
- show rules — правила.
- show jobs — журнал этого сервера.
- show endpoints — доставленные отчёты с временем получения.
- show machine — локальное состояние интерфейса или последний удалённый снимок.
- show ip interface brief / show running-config — базовая сетевая настройка.

Настройки сохраняются вместе с миром автоматически. Ошибки адресов, дубликаты IP,
непрерывность маски и доступ проверяются сервером. Это подмножество CLI NetLab,
а команды приложения не являются командами Cisco IOS.

## VPN на маршрутизаторах

Сервер не содержит VPN-секретов и не вызывает шифрование в своём приложении.
TCP/5420 идёт к локальному IP или через обычный шлюз. Шифрующий роутер меняет
payload на AES-GCM и UDP/4500; принимающий роутер проверяет и восстанавливает
данные, затем передаёт обычный TCP/5420 в свою LAN. ACL проверяются по протоколу
соответствующего участка.

На R1:

    configure terminal
    crypto netlab-vpn peer 10.0.0.2 secret CHANGE-ME-SECRET-123
    end

На R2:

    configure terminal
    crypto netlab-vpn peer 10.0.0.1 secret CHANGE-ME-SECRET-123
    end

Адреса — реальные peer-интерфейсы своего стенда, общий секрет минимум 16
символов. Примерный секрет замени. На сервере в config можно включить vpn required.
Локальная передача без двух роутеров остаётся открытой. Если VPN-политика уже
есть, несовпадение ключей не разрешает откат в открытый режим.

Это учебный VPN NetLab, не полная реализация IPsec/IKE, туннельных внешних
заголовков, NAT-T и всех вариантов port forwarding. Используй маршрутизируемые
адреса конечных устройств. Маршрутизация/криптографическое преобразование
планируются аналитически, эффекты доставки завершаются по серверному времени.

## Перехват, журнал и ограничения

Анализатор получает копии на destination-порту SPAN. В открытом OFFER можно
увидеть билет. Свой сервер с собственным интерфейсом-получателем может предъявить
этот билет через claim — намеренная учебная уязвимость bearer-протокола.
В межроутерном сегменте анализатор видит шифрованные данные, но в LAN до/после
VPN-роутеров трафик открыт. Нужны права управления коммутатором для SPAN или
доступ к уже настроенному порту.

Билет погашается один раз, частичные остатки хранятся в журнале. Обрыв сети,
неверный VLAN/ACL/шлюз, выгрузка или снятие устройства не создают новые предметы.
Снятый сервер нужно вернуть в загруженную сеть с его прежним IP/правилами.
Уничтожение исходного интерфейса не заменяет его новым блоком на тех же
координатах. Если сторонний ItemHandler нарушил контракт вставки, операция
попадает в карантин: нужна ручная сверка, автоматический повтор остановлен.
Гарантировать атомарность стороннего инвентаря при падении процесса невозможно.

Автоматическая совместимость — NeoForge item/fluid/energy capabilities и
ванильные контейнеры. Энергия или lit не доказывают точный прогресс работы.
Специальные действия добавляются через MachineAdapters.Adapter / ADAPTERS.
FakePlayer-клик, обход GUI и систем защиты регионов не добавлены; интеграция
должна учитывать разрешения конкретного мода.

Сборка запускает проверки ядра; отдельно проверен round-trip конфигурации приложения через
Gson и сжатый NBT. Minecraft/Prism/GameTest не запускались. Полная игровая проверка
геометрии, кликов, инвентарей и миграции настоящего сохранения остаётся за игроком.
