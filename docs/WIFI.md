# NetLab 0.8.0-alpha — Wi-Fi

## Быстрый запуск

1. Поставь новый блок «Точка доступа Wi-Fi» из вкладки NetLab.
2. Подключи его единственный Ethernet-разъём медным кабелем к LAN-порту
   коммутатора или роутера. На роутере настрой DHCP для этой LAN.
3. ПКМ по точке открывает настройки: SSID, Open/WPA2-PSK, пароль, канал
   1–11, радиус 4–64 блока, изоляция клиентов, радио и питание.
   По умолчанию SSID — NetLab, сеть открытая, радиус — 32 блока.
4. Открой ноутбук → PC Wireless / Wi-Fi → «Адаптер / питание».
   Выключи питание, открой «Модули», выбери radio0 и установи WPC300N.
   В survival нужен предмет карты в инвентаре; creative позволяет установку
   из каталога. Включи питание и закрой физическую панель.
5. На настольном ПК используется PCI-карта WMP300N вместо PCMCIA WPC300N.
6. Выбери найденный SSID, введи пароль при WPA2 и нажми «Подключить / DHCP».
7. Убедись, что появился IP. Закрой Wi-Fi, открой Command Prompt и выполни
   `ipconfig /all`, `ping <IP шлюза>` или ping другого устройства LAN.

Установка адаптера, ассоциация с AP и получение IP — отдельные этапы.
Точка доступа работает мостом и сама не является DHCP-сервером/NAT-роутером.
Управление ею не требует IP — оно доступно через её внутриигровое меню.

## Настройки клиента

После подключения активным IP-интерфейсом становится Wireless0. Поля IPv4
в Desktop, `ipconfig`, `/renew` и `/release` относятся к выбранному адаптеру.
Для статического IP после подключения используй Apply IPv4 в Desktop.
Кнопка «Подключить / DHCP» заново включает DHCP на радиоадаптере.

«Отключить» возвращает выбор Ethernet и сохранённые проводные шлюз/DNS.
При наличии двух адаптеров фоновые DHCP-запросы отправляются только
с выбранного интерфейса. Настройки ПК сохраняются при выключении питания;
копировать running-config на ПК не требуется. После замены карты выбери
SSID и подключись снова.

## Что работает

* Поиск включённых AP с учётом расстояния; сила сигнала отображается в %.
* Open и проверка пароля WPA2-PSK. Пароли маскируются в GUI и не выдаются
  в списке сетей; пароль AP хранится хешем, сохранённый ключ клиента — type 7.
* Несколько клиентов на одной AP, передача клиент–клиент и клиент–LAN.
* Изоляция клиентов запрещает прямой обмен через радио, сохраняя доступ
  к проводной сети. Это локальная функция AP, не замена межсетевому экрану.
* DHCP через мост AP и маршрутизация в другие сети через LAN-шлюз.
* Выход за радиус, выключение питания/радио, снятие карты и неправильный
  пароль действительно убирают рабочий путь передачи.
* Автоподключение к сохранённому SSID при возвращении в зону и выбор более
  близкой подходящей AP с тем же SSID/защитой/паролем.
* Настройки и профили сохраняются в мире; текущая ассоциация пересчитывается
  по загруженным устройствам раз в секунду и при сетевых операциях.
* В очках видны фиолетовые маркеры реальных передач по воздуху.
  Скорость и пауза показа — `/netlab study`.

## HWIC-AP-AG-B

Существующий модуль стал рабочей точкой доступа. Установи его в выключенный
совместимый роутер, включи устройство, открой Physical → Wi-Fi.
Настрой SSID/защиту и создай SVI VLAN 1 с адресом шлюза через Console:

```text
enable
configure terminal
interface vlan 1
ip address 192.168.9.1 255.255.255.0
no shutdown
```

Радио модуля входит во встроенный L2-домен роутера. DHCP-пул на роутере
настраивается для этой подсети. Встроенный маршрутизируемый Ethernet-порт
может обслуживать другую подсеть; трафик Wi-Fi проходит к ней через SVI.
Обе ячейки шкафа поддерживаются.

## Границы модели

Радиоканал — часть учебного сетевого графа. Это не подключение к настоящему
Wi-Fi компьютера. WPA2 здесь проверяет доступ, без побайтового AES/802.11
handshake. Дальность рассчитывается по расстоянию между блоками; стены,
материалы, радиопомехи, перекрытие каналов и RF-модуляция пока не моделируются.
Канал отображается и сохраняется; клиент подстраивается под AP автоматически.
Переключение AP происходит синхронно при пересчёте, без таймеров roaming.
Топология строится только по уже загруженным устройствам одной размерности,
без принудительной загрузки чанков, максимум 1024 сетевых узла.

Пока одна конфигурация SSID на устройство, без multi-SSID, WLC, WPA-Enterprise,
RADIUS и привязки разных SSID к разным VLAN. Обычный AP подключай к access,
не к тегированному trunk. Скрытые сети не настраиваются через GUI.

## Проверка

`./dev.sh build`: 285 core-проверок. Проверены сканирование, отдельный
Wireless0, WPA2 и неверный пароль, DHCP/проводной шлюз, радиус/питание/радио,
несколько клиентов и изоляция, выбор ближайшей AP, снятие адаптера,
WPC300N/WMP300N, сохранение профиля, рабочий HWIC-AP и маршрутизация через
SVI в другую подсеть, переключение обратно на Ethernet.

Minecraft, Prism и GameTest не запускались. GUI и модели скомпилированы;
внешний вид и пользовательский проход нужно проверить в игре.
