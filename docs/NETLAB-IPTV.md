# IPTV: настройка по устройствам

NetLab Media 0.1.0, NetLab 0.22.0, Sputnik 0.3.0, Minecraft 1.21.1 / NeoForge 21.1.265. Для видео на клиенте нужен Rinku 3.0.4; Simple Voice Chat — общая обязательная зависимость Media для телефонии. Это самостоятельный раздел «Библии по CISCO».

## 1. Как устроен стенд

Источники видео → интернет-шлюз Sputnik → медиасервер IPTV → коммутатор → IPTV-приставка → HDMI → телевизор.

Медиасервер хранит каналы, плейлисты и общую временную шкалу. Приставка подключается к игровому IP сервера и выбирает канал. Телевизор получает картинку через HDMI и выводит звук встроенными динамиками или через аудиокабель.

YouTube открывается официальным встроенным плеером каждого зрителя. Это синхронный эфир из ссылок, а не повторное кодирование YouTube в multicast. Сетевые байты проходят игровую цепочку шлюз → медиасервер → приставка; состояние маршрута проверяет сервер.

## 2. Сначала оборудование, питание и память

Нужны медиасервер, коммутатор, ПК/ноутбук, приставка, телевизор, Ethernet и HDMI. Для внешнего звука — аудиокабель, аудиоразветвитель и колонки.

Медиасервер занимает одну из двух ячеек шкафа. Снять его можно отвёрткой Shift+ПКМ после отключения кабелей. На выключенный медиасервер и приставку установи карты памяти CISCO, затем включи питание. Пустая карта включает автозапись; write memory явно сохраняет настройки.

Питание: генератор/FE → энергошкаф → IN блока питания шкафа → OUT → задний FE каждого устройства. Медиасервер расходует 12 FE/тик, телевизор 4, приставка/разветвитель/колонка по 2. Коммутатор питается отдельно по общим правилам NetLab. У ноутбука должна быть заряжена батарея.

Базовый медиасервер поддерживает 4 канала. Плата NL-MEDIA-VIDEO в video0 повышает лимит до 16; устанавливается только при Power OFF. Увеличение числа каналов не увеличивает пропускную способность кабелей.

## 3. Подключить кабели: порт к порту

Медиасервер GigabitEthernet0/0 ↔ Ethernet ↔ коммутатор.
ПК Ethernet ↔ Ethernet ↔ другой порт коммутатора.
Приставка GigabitEthernet0/0 ↔ Ethernet ↔ другой порт коммутатора.
Приставка HDMIOut ↔ HDMI ↔ телевизор HDMIIn.

Console — только для терминала, это не сетевой RJ45. Аудиокабель не передаёт изображение; HDMI не вставляется в Ethernet. Названия и точные точки подключения видны в очках.

Для команд ПКМ портативным терминалом по Console нужного устройства либо ноутбук RS232 → консольный кабель → Console. Для управления каналами используется отдельное приложение на ПК/ноутбуке.

## 4. Адресный план: что куда вписывать

Все адреса ниже существуют внутри Minecraft. Маска в примере 255.255.255.0.

Медиасервер GigabitEthernet0/0: 192.168.50.10.
ПК Ethernet: 192.168.50.100.
Первая приставка GigabitEthernet0/0: 192.168.50.20.
Вторая приставка при необходимости: 192.168.50.21.
Маршрутизатор этой LAN, если нужен выход в другую сеть: 192.168.50.1.

В поле «IP медиасервера» приставки и в приложении управления вводится 192.168.50.10. Это не шлюз. Шлюзом устройств при выходе за пределы LAN будет 192.168.50.1. Для обмена внутри одной подсети шлюз не обязателен.

IP настоящего сайта не назначается ни приставке, ни серверу. Адрес интернет-шлюза Sputnik берётся из реально настроенного спутникового стенда.

## 5. Console медиасервера: первый запуск

Где вводить: Console самого медиасервера, не терминал ПК Command Prompt. MediaPass2026 — пример; выбери свой пароль.

```text
enable
configure terminal
hostname IPTV
interface gi0/0
ip address 192.168.50.10 255.255.255.0
no shutdown
exit
media admin MediaPass2026
media enabled on
end
write memory
show media
```

media admin — собственная команда NetLab Media, не Cisco IOS. Пароль даёт доступ к управлению с ПК. Консоль физического сервера доступна владельцу устройства. Пароль и ссылки не публикуются в общих данных топологии.

Если внешние источники доступны через другой сегмент, здесь же задай ip default-gateway 192.168.50.1 в configure terminal. Проверь прямые и обратные маршруты.

## 6. Настроить настоящий интернет-выход

Где вводить: Console медиасервера. Сначала собери и проверь Sputnik по разделу «Спутниковая связь». Впиши игровой LAN IP работающего интернет-шлюза Sputnik, например 172.30.88.2, только если именно такой IP у твоего блока.

```text
enable
configure terminal
iptv gateway 172.30.88.2
end
write memory
```

192.168.50.1 — ближайший маршрутизатор медиасервера, а 172.30.88.2 — удалённый блок интернет-выхода. Это разные адреса. У шлюза должен быть рабочий HUB/VSAT-тракт; одних проводов и включённой кнопки internet недостаточно.

Для запросов и ответов нужны маршруты медиасервер ↔ шлюз и медиасервер ↔ приставка. Интернет используется на стороне Minecraft-сервера; локального обхода отсутствующей игровой сети у телевизора нет.

## 7. ПК/ноутбук: войти в управление IPTV

Настрой Ethernet ПК: IP 192.168.50.100, маска 255.255.255.0; шлюз 192.168.50.1 только при необходимости. В Command Prompt проверь ping 192.168.50.10.

Открой Desktop → «IPTV / АТС» → IPTV. IP сервера: 192.168.50.10. Пароль: тот, который задан командой media admin на медиасервере. Нажми «Подключиться».

Успешный ping проверяет сетевую доступность, но не заменяет пароль приложения. При подключении учитываются оба направления маршрута.

## 8. Создать и занять телеканал

Где: приложение управления IPTV после входа. Номер 7, название Cisco Music → «Создать / переименовать».

Номер уникален на этом медиасервере; у другого оператора может быть свой канал 7. У канала записывается владелец — игрок, который его создал. Владелец медиасервера может управлять всеми каналами; другие пользователи с доступом к приложению — своими или разрешёнными им каналами.

То же в Console медиасервера после enable → configure terminal:

```text
iptv channel 7 Cisco Music
```

Для выдачи редакторского доступа: iptv grant 7 UUID_ИГРОКА. Для отзыва: iptv revoke 7 UUID_ИГРОКА. UUID — идентификатор Minecraft-персонажа редактора, не IP устройства и не ID антенны. Просмотр эфира пароля администратора не требует.

## 9. Добавить видео и запустить эфир

Где: приложение IPTV. Выбери номер канала, вставь ссылку, укажи длительность в секундах и нажми «Добавить в плейлист». Повтори для следующих роликов, затем «В эфир».

В этой версии длительность задаётся вручную: она нужна серверу для единого расписания даже без зрителей. По умолчанию поле содержит 180 секунд. Если ролик длиннее, увеличь значение; иначе сервер переключит канал раньше конца видео. Очередь идёт в порядке добавления, до 64 записей на канал. Удаление по номеру записи начинается с 1 и сбрасывает временную шкалу канала.

Команды Console:

```text
iptv add 7 180 https://www.youtube.com/watch?v=M7lc1UVf-VE
iptv start 7
iptv loop 7 on
```

Это пример ссылки, её доступность проверяй в своём окружении. Кнопки «Каналы» и «Плейлист» открывают списки. Для изменения очереди укажи номер записи и новую позицию → «Переместить видео». В Console это iptv move 7 2 1 — переместить вторую запись на первое место. Перестановка начинает временную шкалу канала заново. Для остановки: iptv stop 7. Для удаления второй записи: iptv remove 7 2. Тот, кто подключился через минуту после начала, смотрит текущую минуту эфира. Смена канала одного телевизора не перематывает эфир остальных.

## 10. Console приставки и первый просмотр

Где вводить: Console IPTV-приставки.

```text
enable
configure terminal
interface gi0/0
ip address 192.168.50.20 255.255.255.0
no shutdown
exit
iptv server 192.168.50.10
iptv tune 7
end
write memory
```

Затем ПКМ по телевизору → «Смотреть / управление плеером». Если источник запрещает автозапуск со звуком, нажми кнопку Play непосредственно на плеере. После закрытия меню изображение остаётся на телевизоре в мире, пока он рядом и эфир доступен.

Вторая приставка получает свой уникальный IP 192.168.50.21; сервер и номер канала указываются те же. У зрителей синхронизируется позиция передачи; реклама и ограничения YouTube могут различаться.

## 11. Встроенный звук, разветвитель и колонки

Телевизор AudioOut → аудиокабель → AudioIn разветвителя. AudioOut1..4 разветвителя → отдельные AudioIn колонок. Разветвитель и колонки должны получать FE.

ПКМ по телевизору позволяет отключить встроенные динамики, оставив внешние. ПКМ по разветвителю или колонке — громкость. Общая громкость источника умножается на громкость последующих устройств. Колонки слышны в пределах 32 блоков с затуханием.

Разветвители можно соединять последовательно: до 8 ступеней и 16 выходных точек на источник. Замкнутые аудиопетли не дублируют сигнал. Одновременно на клиенте воспроизводится до 32 звуковых точек всех источников. Поддерживаются колонки Media и Sputnik. Такой же разветвитель можно подключать к AudioOut ПК с браузером Sputnik.

## 12. Другая подсеть, VLAN и очки

Сначала добейся просмотра в одном LAN. Затем перенеси приставку в другую сеть: ей нужен шлюз в её собственной подсети, медиасерверу — шлюз в своей. Маршрутизатор должен знать обе сети, а ACL — пропускать обмен.

Передача видео в 0.1.0 идёт отдельными TCP-потоками зрителей, управление Media — порт 8080, тракт видео от медиасервера к приставке — 5004. Пакеты занимают очереди NetLab; контроллер скорости и существующие VLAN/ACL/VPN влияют на передачу. Очки показывают путь с отметкой IPTV.

Настоящего IGMP/multicast в этой версии нет. Не вводи команды multicast из реальной документации в ожидании работы: этот режим требует отдельного обновления сетевого ядра.

## 13. Диагностика по порядку

«Нет питания»: FE, задний порт, OUT блока питания, Power ON. «Подключи HDMI приставки»: HDMIOut приставки должен приходить в HDMIIn телевизора. «Канал не вещает»: правильный сервер, номер, непустой плейлист и команда start.

«Нет маршрута IPTV туда / обратно»: IP и маски, состояние Ethernet, VLAN, шлюзы, обе стороны маршрута и ACL. «Нет сигнала» при пустом адресе: сначала задай iptv server на приставке.

Чёрный или ошибочный плеер при ON AIR: проверь рабочий Sputnik, iptv gateway, доступность самого источника, Rinku и кнопку Play. ON AIR означает выбранный работающий канал, но не гарантирует успешный ответ внешнего сайта.

Нет звука: громкость Minecraft, звук источника, встроенные динамики, IN/OUT разветвителя, питание колонок и расстояние. При закрытии меню настройки должны сохраняться; для сохранения после перезагрузки сетевых устройств нужна активная карта CISCO.

## 14. Демо и границы первой версии

Операторская команда /netlab demo media строит проверенный по свободному месту стенд 12×8×3 к югу от игрока и выдаёт книгу с фактическими адресами и случайным паролем. Существующие постройки не заменяются. /netlab media kit выдаёт набор без строительства.

Телефония демо готова для двух игроков. Для IPTV добавь своё видео, его длительность и подключи существующий интернет-шлюз Sputnik: демо Media не строит спутниковую инфраструктуру.

Поддерживаются YouTube и прямые HTTP/HTTPS видео, которые способен воспроизвести установленный Chromium. Не обещается поддержка любых сайтов, DRM, кодеков, прямого эфирного ввода, HLS/DASH-плейлистов и покадрово одинаковой рекламы. До 4 одновременно воспроизводимых телевизоров на клиенте в радиусе 32 блоков. Выделенный сервер не запускает Chromium. Windows/Linux должны проверяться игровым клиентом отдельно.
