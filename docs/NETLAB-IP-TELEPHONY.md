# IP Телефония: настройка по устройствам

NetLab Media 0.1.0, NetLab 0.22.0, Sputnik 0.3.0, Minecraft 1.21.1 / NeoForge 21.1.265. Для микрофона нужен Simple Voice Chat 1.21.1 NeoForge на сервере и у обоих игроков. Для Pocket дополнительно нужен Mobile 0.4.0. Это отдельный раздел «Библии по CISCO».

## 1. Как устроен звонок

IP-телефон 1001 → коммутатор → сервер IP-АТС ← коммутатор ← IP-телефон 1002.

АТС хранит номера и пароли регистрации, принимает REGISTER, устанавливает вызов INVITE и получает BYE при завершении. После ответа голос идёт отдельным двусторонним потоком непосредственно между аппаратами. На уровне NetLab голос использует UDP, контроль звонка — учебные сообщения SIP-последовательности. Это внутриигровая реализация: подключения к настоящей АТС или реальным телефонным номерам нет.

Номер 1001 — имя абонента на АТС; IP 192.168.60.20 — адрес самого аппарата. Пароль абонента не является паролем входа на Minecraft-сервер.

## 2. Оборудование, питание и память

Поставь сервер IP-АТС в одну ячейку шкафа, подключи его LAN к коммутатору. Два настольных телефона подключаются к другим портам Ethernet.

У АТС и каждого настольного телефона при Power OFF установи карту памяти CISCO. Подключи задний FE-вход каждого устройства к OUT блока питания шкафа. АТС расходует 12 FE/тик, телефон 2. Включи Power. Затем после настройки выполняй end → write memory.

В этой версии телефоны питаются отдельным FE-кабелем; PoE ещё не реализован. Плата NL-MEDIA-SESSIONS в sessions0 увеличивает ёмкость одной АТС с 8 до 24 одновременных звонков; устанавливается при выключенном питании.

## 3. Адресный план: IP и номера

Одна LAN, все маски 255.255.255.0:

IP-АТС GigabitEthernet0/0 — 192.168.60.10.
Телефон A GigabitEthernet0/0 — 192.168.60.20, номер 1001.
Телефон B GigabitEthernet0/0 — 192.168.60.21, номер 1002.
ПК управления при необходимости — 192.168.60.100.
Маршрутизатор, если соединяем разные сети — 192.168.60.1.

Для звонка в этой LAN шлюз не обязателен. На обоих телефонах в поле «IP АТС» пишется 192.168.60.10. В поле «Свой номер» — 1001 или 1002, а не IP телефона.

## 4. Console АТС: первый запуск

Где вводить: Console сервера IP-АТС. AdminMedia2026 — пример, выбери свой пароль.

```text
enable
configure terminal
hostname PBX
interface gi0/0
ip address 192.168.60.10 255.255.255.0
no shutdown
exit
media admin AdminMedia2026
media enabled on
end
write memory
show sip
```

media admin включает пароль приложения управления. Это собственная команда Media; сетевые команды остаются обычными командами NetLab. Она не создаёт телефонный номер.

## 5. Console АТС: создать двух абонентов

Где вводить: та же Console АТС, после enable → configure terminal.

```text
sip user 1001 PhoneA2026
sip user 1002 PhoneB2026
end
write memory
show sip
```

Пароли PhoneA2026 и PhoneB2026 — только примеры. На телефоне A вводится пароль именно номера 1001. Административный пароль от media admin в аппарат не вводится.

Номер содержит 2..12 цифр, пароль 8..64 символа без пробелов. До 64 абонентов на одной АТС. Повторная команда sip user меняет пароль и отзывает старую регистрацию. Удаление: sip delete 1002 в configure terminal. После изменения — write memory.

## 6. Console телефона A: настроить сеть

Где вводить: Console первого настольного телефона.

```text
enable
configure terminal
interface gi0/0
ip address 192.168.60.20 255.255.255.0
no shutdown
exit
sip server 192.168.60.10
sip account 1001 PhoneA2026
end
write memory
```

Через секунду телефон начинает регистрацию. Должен появиться статус REGISTERED. Для второго аппарата повтори команды в его Console с IP 192.168.60.21, номером 1002 и паролем PhoneB2026.

Одного кабеля недостаточно: оба телефона должны знать IP АТС, а на АТС должны существовать соответствующие номера.

## 7. Меню телефона: регистрация и проверка

ПКМ по телефону открывает его панель. Если сеть уже настроена через Console, можно указать «IP АТС», «Свой номер» и «Пароль регистрации» в меню → «Сохранить и зарегистрировать».

Пароль не показывается обратно в интерфейсе. Поле остаётся пустым при новом открытии; это не означает, что сохранённый пароль пропал. Повторно заполняй его только при изменении регистрации.

На АТС show sip показывает настроенные номера и число зарегистрированных аппаратов. Без REGISTERED проверяй сначала сеть и регистрацию, затем микрофон.

## 8. Микрофон и Simple Voice Chat

Установи Simple Voice Chat NeoForge 1.21.1 на сервер и на оба клиента. В подготовленной сборке используется 2.6.27. В его меню выбери микрофон и устройство вывода, проверь локальный тест записи, настрой клавишу Push To Talk или активацию голосом.

У выделенного сервера должен быть доступен UDP 24454 — это стандартный порт Simple Voice Chat. Открытого TCP 25565 для микрофона недостаточно. Это реальный UDP-порт хоста, а SIP 5060 и RTP 16384 в NetLab — порты внутри игровой сети.

Мод Media не включает микрофон сам: действует выбранный пользователем режим Simple Voice Chat. В активном звонке голос направляется по телефонному соединению, обычная рассылка этого микрофонного пакета в proximity-чат отменяется.

## 9. Первый разговор двух игроков

Игрок A подходит к первому телефону, ПКМ, набирает 1002 → «Позвонить». На телефоне B звучит звонок. Игрок B подходит к нему, открывает меню → «Ответить».

Статус ACTIVE означает установленный разговор. Сверни меню Esc, оставайся рядом с настольным аппаратом и говори с настроенной клавишей микрофона. Закрытие меню активного вызова не кладёт трубку. Телефон занят одним использующим его игроком.

Для завершения открой тот же телефон и нажми «Завершить». Уход дальше 8 блоков, исчезновение устройства, отключение питания или потеря регистрации завершают разговор. Неотвеченный вызов завершается через 30 секунд. Самому себе позвонить нельзя.

## 10. Трубка и громкая связь

По умолчанию ответ собеседника слышит игрок, использующий трубку. Кнопка «Громкая связь» включает пространственное воспроизведение возле аппарата — его могут услышать окружающие в пределах 12 блоков.

Кнопка громкой связи изменяет вывод принимаемого голоса, а не увеличивает дальность сети. Для отключения собственного микрофона используй mute Simple Voice Chat. Музыкальные колонки и аудиоразветвитель относятся к медиазвуку телевизора/браузера; телефонная громкая связь в 0.1.0 использует свой аудиоканал.

## 11. Cisco Pocket: звонки через мобильную сеть

Нужны Mobile 0.4.0 и Media. Установи в Pocket предмет «Модуль IP-телефонии Cisco Pocket» через «Модули», вставь активную SIM и держи телефон в руке до регистрации в сети.

Pocket → «Приложения» → «IP-телефония». IP АТС: например 192.168.60.10. Создай на этой АТС отдельный номер 1003 с собственным паролем и впиши их в приложение → «Сохранить и зарегистрировать».

IP Pocket получает от EPC, вручную адрес 192.168.60.20 ему не назначается. Номер выдаёт АТС, SIM разрешает вход в мобильную сеть. IP АТС должен быть доступен из мобильного пула и обратно.

После регистрации можно звонить 1001/1002 и другим Pocket. При входящем звонке телефон подаёт сигнал и показывает уведомление: открой приложение и ответь. Разговор продолжается после сворачивания меню, пока Pocket в руке, модуль установлен и есть мобильная связь. Настройки приложения сохраняются в самом предмете телефона.

## 12. Мобильный и настольный абоненты: маршруты

Путь: Pocket → антенна → RRU → BBU → EPC → маршрутизатор → LAN АТС / настольного телефона. Сначала проверь, что работают сама мобильная сеть и диагностика IP.

Если мобильный пул 10.64.0.0/24, а АТС и настольные аппараты находятся в 192.168.60.0/24, маршрутизатор телефонной LAN должен знать путь к 10.64.0.0/24 через EPC. У АТС и настольных телефонов должен быть правильный шлюз для ответов мобильному пулу. Адрес следующего перехода бери с LAN-интерфейса своего EPC, не с IP телефона.

Успешный REGISTER проверяет путь телефон ↔ АТС. После ответа RTP идёт телефон ↔ телефон. Поэтому доступная АТС при закрытом межабонентском маршруте даёт звонок без звука.

## 13. Voice VLAN, задержка и защита

Начни с одного LAN. Затем выдели телефоны в отдельный VLAN общими настройками коммутатора и обеспечь маршрутизацию к АТС и другим аппаратам. Специальной автоматической выдачи Voice VLAN через LLDP/CDP и provisioning в Media 0.1.0 нет.

Контроль вызова использует игровой UDP 5060, голос UDP 16384. Очки показывают SIP/RTP-отметки, фактическую длину пути и очереди. Существующий контроллер скорости NetLab влияет на доставку. При большой задержке устаревший голос отбрасывается, а не накапливается бесконечной записью. Буфер ограничен.

Защиту межсетевого трафика выполняют маршрутизаторы NetLab с настроенным VPN. АТС сама VPN не создаёт. TLS/SRTP как отдельные протоколы Media пока не реализованы; реальное транспортное шифрование Simple Voice Chat не заменяет настройку игровой сети.

## 14. ПК/ноутбук: управление абонентами

Открой Desktop → «IPTV / АТС» → «IP-АТС». IP сервера: 192.168.60.10. Пароль: AdminMedia2026 из media admin, а не пароль телефона.

После входа можно создавать номера, менять пароль и удалять абонентов. Адреса и имена интерфейсов по-прежнему настраиваются в Console оборудования. ПК в этой версии управляет АТС, но сам не является софтфоном.

## 15. Диагностика по порядку

Не зарегистрирован: питание, LAN, IP/маска, no shutdown, правильный IP АТС, существующий номер, его пароль, прямой и обратный маршруты. Один номер одновременно занимает один аппарат.

Абонент недоступен: второй телефон включён, зарегистрирован на этой же АТС и имеет другой номер. Занято: он уже участвует в другом вызове. У двух независимых АТС одинаковые номера не объединяются автоматически.

ACTIVE без звука: Simple Voice Chat установлен у обоих, реальный UDP-порт доступен, микрофон выбран, PTT/mute проверены, меню свёрнуто при необходимости. Затем проверь игровой путь между аппаратами, а не только ping АТС.

Звук в одну сторону: маршруты и ACL между IP аппаратов в каждом направлении, шлюз настольного телефона для мобильного пула. Обрывы Pocket: активная SIM, телефон в руке, покрытие и доступность EPC.

## 16. Демо и расширения

/netlab demo media — операторская команда строительства стенда. Два аппарата уже имеют номера 1001 и 1002, АТС и коммутатор настроены, питание подключено. Фактические IP и случайный пароль записаны в выданной книге. Нужны два игрока с работающим Simple Voice Chat.

В Media 0.1.0 реализованы звонки в пределах одной АТС, включая аппараты в разных подсетях и мобильных абонентов. SIP-транки между АТС, настоящая интеграция с внешним SIP-провайдером, IMS/VoLTE, PoE, конференции и TLS/SRTP — будущие расширения, их команды не включены в эту инструкцию как работающие.
