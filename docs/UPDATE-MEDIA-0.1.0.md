# NetLab Media 0.1.0-alpha

IPTV-каналы с общей временной шкалой и IP-звонки через микрофон добавлены отдельным JAR `netlab-media-0.1.0-alpha.jar`. Требуются NetLab 0.22.0, Sputnik 0.3.0, Simple Voice Chat 1.21.1-2.6.27 на обеих сторонах и Rinku 3.0.4 на клиенте. Для Cisco Pocket нужен Mobile 0.4.0. Automation 0.7.3 остаётся совместимым.

## Что добавлено

- Медиасервер и IP-АТС для двух штатных ячеек серверного шкафа, отдельные Console и Ethernet, физические порты и заднее FE-питание.
- IPTV-приставка, телевизор с изображением в мире, встроенным звуком и экранным плеером; HDMI-кабель.
- Каналы с владельцем, разрешёнными редакторами, очередью до 64 видео, перестановкой/удалением, повтором и общим серверным расписанием. Номер уникален в рамках медиасервера.
- Приложение управления IPTV/АТС на ПК и ноутбуке с входом по игровому IP и паролю службы. Списки каналов и видео; сохранение вводимых значений при сетевых ответах, прокрутка коротких экранов.
- Аудиоразветвитель 1→4, колонки Media и совместимость с колонками/браузерным звуком Sputnik. Направленные подключения IN/OUT, ограничение глубины цепи и защита от петель.
- IP-телефон с настоящим микрофонным разговором через Simple Voice Chat. Регистрация на АТС, вызов, ответ, занято, завершение, громкая связь и освобождение трубки при уходе.
- Модуль IP-телефонии для Pocket: активная SIM, мобильная сеть, свой номер и SIP-приложение. Настройки хранятся в физическом предмете телефона.
- Две аппаратные платы: NL-MEDIA-VIDEO расширяет число каналов 4→16, NL-MEDIA-SESSIONS число одновременных звонков АТС 8→24.
- 12 рецептов и отдельная творческая вкладка NetLab Media.
- Два раздела «Библии по CISCO»: IPTV (14 глав), IP Телефония (16 глав). Одни и те же тексты публикуются в книге и в Markdown.
- `/netlab media kit` и `/netlab demo media` для оператора. Демо проверяет свободное место до строительства и выдаёт книгу с фактическими адресами и случайным паролем; спутниковый тракт для внешнего видео подключается отдельно.

## Сетевая модель

SIP-последовательность моделируется сообщениями через игровые UDP-пакеты 5060. Голос Opus проходит непосредственно между аппаратами по UDP 16384 и доставляется только после завершения очереди NetLab. Захват микрофона/реальный UDP-транспорт предоставляет Simple Voice Chat, а доступность и получателей контролирует Media. Во время разговора стандартная proximity-рассылка этих микрофонных пакетов отменяется.

Каждый внешний видеозапрос проходит через SOCKS-транспорт Sputnik и реальные игровые участки приставка ↔ медиасервер ↔ интернет-шлюз. В Chromium нет прямого fallback в обход отсутствующего игрового соединения. Декодирование выполняется клиентом, отдельный Chromium на выделенном сервере не нужен.

Новые приложения используют существующие VLAN, маршрутизацию, ACL, очереди и маршрутизаторный VPN. При смене аппаратной конфигурации, карты, пароля или регистрации старые привязки проверяются повторно.

## Границы версии

Это синхронные плееры YouTube/прямых браузерных видео и отдельные потоки зрителей. Настоящий multicast/IGMP, перекодирование на сервере и универсальная поддержка любых сайтов/DRM/HLS не реализованы. Длительности видео вводятся в плейлисте вручную. Реклама и ограничения источников могут отличаться между зрителями. Не более четырёх активных телевизионных плееров на клиенте.

Звонки работают внутри одной АТС, в том числе через маршрутизаторы и мобильную сеть. Это SIP-приложение поверх мобильного интернета; IMS/VoLTE, SIP-транки, внешние телефонные провайдеры, PoE, отдельные TLS/SRTP и конференции не реализованы. ПК управляет услугами, но не работает софтфоном.

Интерфейсы и поведение в Minecraft требуют ручной проверки. Minecraft, выделенный сервер, мир и GameTest для тестирования этого обновления не запускались. Микрофон и настоящий разговор двух игроков не проверялись. Windows нативно не проверялась.

## Проверки

- 10 085 проверок ядра, включая 569 новых проверок расписания, состояний звонка, сетевых портов, UDP-передачи и нового модуля Pocket.
- 401 проверка реальных реестров Media, карт памяти, сериализации предметов, доступности физических портов на моделях, кодеков пакетов и текста книги.
- 7 проверок фактического интерфейса Simple Voice Chat API: жизненный цикл, отмена proximity-рассылки в разговоре, стабильность аудиоканала и его завершение. Использованы подменные сетевые соединения API, без микрофона.
- 1218 проверок 88 рецептов и достижимости 132 предметов в выживании по всем пяти модам, включая все 17 физических предметов кабелей.
- Standalone Chromium на Linux из установленного Rinku: страница плеера загрузилась через `HtmlResource`, тестовый WebM декодировался, получены кадры и PCM, команда синхронизации изменила позицию воспроизведения. Ни Minecraft, ни микрофон не запускались. Это не проверка YouTube, реального спутникового тракта или картинки телевизора в игре.

Команды повторения:

```bash
./dev.sh --offline build
python tools/check_media.py
python tools/generate_media_assets.py
python tools/generate_media_guides.py
python tools/package_mods.py
```

Для отдельной проверки Chromium сгенерируй локальный WebM с видео и звуком, скомпилируй `tools/MediaChromiumRuntimeCheck.java` с media runtime classpath и запусти, передав каталог native JCEF и путь к WebM. Проверка не обращается к внешним видео и не включает микрофон.

Документация зависимостей: [Simple Voice Chat API](https://modrepo.de/minecraft/voicechat/api/getting_started), [UDP-порт голосового сервера](https://modrepo.de/minecraft/voicechat/wiki/server_config), [официальный плеер YouTube](https://developers.google.com/youtube/iframe_api_reference).
