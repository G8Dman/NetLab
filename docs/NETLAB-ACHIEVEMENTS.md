# NetLab Academy: полный список достижений

**Статус:** каталог NetLab Academy 0.1.0 для NetLab 0.23.0. Учебный маршрут и прогресс встроены в «Библию по CISCO», раздел «Обучение». Отдельного учебного экрана нет.

Название дополнения — **NetLab Academy**, mod ID — `netlabacademy`. Цель: провести новичка по работающим возможностям NetLab и установленных дополнений, объясняя цель действия и способ проверки результата.

Каталог содержит 215 заданий для NetLab, Automation, Mobile, Sputnik и Media. Из таблиц генерируются данные дополнения; серверные наблюдатели отслеживают действия и результаты работы оборудования. Сборка и проверки выполняются без запуска Minecraft. Полный ручной прогон заданий в мире пока не проводился.

## Как устроено дерево

- Основной курс состоит из **29 крупных шагов**, а дополнительные карточки помогают разобраться глубже. Финал курса проверяет также реальные необходимые зависимости этих шагов.
- Корень «Добро пожаловать» открыт сразу. Карточки ближайших задач видны заранее; выполненная предыдущая задача выделяет следующий шаг. Новичок должен видеть, что делать дальше.
- Каждая карточка содержит: цель, список оборудования, точное место настройки, подсказку, ссылку на раздел «Библии», проверяемый результат и пояснение частых ошибок.
- В таблицах приведены короткие ID. Технические ID — только в нижнем регистре, например `netlabacademy:base/b01`, `netlabacademy:automation/a10`.
- Запись родителей через запятую означает **И**: нужны все перечисленные задачи. Предлагаемый граф зависимостей должен дополняться фактическими условиями задания, а не заменять их.
- Сложные ветки не обязательны для базового выпуска: OSPF, IPv6, STP, защита сети и межмодовые задания остаются самостоятельным углублением.
- Награды по умолчанию учебные: значок, отметка прогресса, следующая подсказка. Бесплатные платы, FE, предметы и административные полномочия не выдаются.

## Главное правило: нет аддона — нет его достижений

Условия определяются **загруженными на сервере модами**, а не наличием файлов в папке и не списком модов только на клиенте.

| Ветка | Нужные mod ID |
|---|---|
| Основы, шкаф, консоль, LAN, маршруты, Wi-Fi, диагностика | `netlab` |
| Automation | `netlab` + `netlabautomation` |
| Mobile | `netlab` + `netlabmobile` |
| Sputnik | `netlab` + `netlabsputnik` |
| IPTV | `netlab` + `netlabsputnik` + `netlabmedia` |
| IP Телефония | `netlab` + `netlabmedia` + `voicechat`; зависимости самого Media должны быть удовлетворены |
| Совместные задания | Только при наличии всех модов конкретной строки в таблице условий ниже |
| Carry On / MineColonies / AE2 | Только при наличии соответствующего стороннего мода; для AE2 дополнительно нужна указанная серверная настройка |

**Отсутствующая ветка вообще не загружается в дерево:** нет пустой вкладки, заблокированного значка, подсказки про отсутствующий предмет или ссылки на несуществующего родителя. Обычного флага «скрыто до выполнения» недостаточно.

Корни дополнений опираются на общие базовые достижения; базовый маршрут не ссылается на необязательные ветки. Нельзя держать для отсутствующего аддона обязательный критерий общего финала. Для текущего Media нужно учитывать его реальную зависимость от Sputnik: выключенный Sputnik не делает Media автономным.

При удалении дополнения его ветка исчезает, а ранее заработанный прогресс сохраняется по ID без загрузки классов отсутствующего мода. При возвращении совместимой версии прогресс восстанавливается; старые отметки не должны создавать предметы или доступ к удалённым службам. Итог по установленной сборке пересчитывается для текущего набора веток.

## Условия зачёта и многопользовательская игра

1. Настройка засчитывается по результату на сервере. Ввод `ping` без ответа, наличие текста `REGISTERED` в пользовательском вводе и открытие меню без успешного действия не являются выполнением задания.
2. Для действий в терминале засчитывается как полная команда, так и поддержанное сокращение. Для сохранения основной вариант — `write memory`; чтение карты — `memory read`. Успех открытия GUI не подменяет сохранение.
3. Установка, конфигурация, передача и исправление неисправности привязываются к инициировавшему игроку и идентичности устройств. Простое стояние возле чужой готовой сети не закрывает весь курс.
4. Для совместной работы сохраняется вклад участников: например, один настроил АТС, другой телефон. Достижение разговора получают оба реально участвовавших игрока; настройка всей сети одному игроку не обязательна.
5. Готовый демонстрационный стенд, импорт карты или полученная от друга вещь могут служить учебным оборудованием. Они не выдают автоматически достижения за изготовление и настройку; достижение успешного использования можно заработать своим действием.
6. Не требовать намеренного разрушения чужой сети, перехвата чужих вещей, опасного перегрева сервера или потери предметов. Задания диагностики и защиты выполняются на своём учебном стенде.
7. Базовый курс не требует OP, креатива, творческого генератора, перезапуска сервера или конкретного стороннего технического мода. Источник FE может быть любым совместимым и разрешённым сборкой. Если в сборке вообще нет выживаемого источника FE, это нужно решить до публикации маршрута, а не заставлять новичка добывать творческий генератор.
8. Для аппаратно зависимых заданий нужны отдельные условия доступности. Например, голосовой финал не должен мешать базовому выпуску игрока без микрофона, а реальный сайт — прохождению игрока без внешнего интернета. Политика сервера может исключать такие финалы из обязательного общего итога; они помечаются как отключённые сервисы, а не как отсутствующие моды.
9. Числа слотов, базовые лимиты, питание, типы интерфейсов и рецепты при реализации брать из действующих данных мода. Не зашивать устаревшие параметры только из текста этой методички.

Дополнение не должно выдавать F01 только за перечисленные ID, игнорируя их родителей или результат работы.

## Финалы веток и общий итог

F03 не требует получить каждую пасхалку, каждое диагностическое достижение или каждую межмодовую комбинацию. При предложенных настройках учебные финалы следующие:

| Ветка | Обязательный учебный результат для этой ветки |
|---|---|
| Основной мод | F01: базовый маршрут; F02 — отдельная итоговая практическая работа |
| Automation, если установлен | A11: доставка из графического приложения; A15: реально сработавшее правило; A20: жидкость только если сервер предоставляет подходящие резервуары |
| Mobile, если установлен | M11: подтверждённая передача с Pocket через собственную действующую радиосеть |
| Sputnik, если установлен и внешний интернет разрешён | S12: подтверждённая загрузка страницы через настроенный спутниковый выход |
| IPTV, если Media установлен и внешнее видео разрешено | T10: реально декодированное изображение на настроенном телевизоре |
| IP Телефония, если Media установлен и голосовое обучение включено | V09: голосовой обмен двух участников; не просто зарегистрированные аппараты |

При одном основном NetLab F03 закрывается после базового курса. При установленной Automation без Mobile задачи Pocket даже не появляются. При Media без Mobile остаются IPTV и настольная IP-телефония, но отсутствуют X04–X06. Добавление нового дополнения не стирает уже заработанный значок F03; для расширившейся программы показывается новый незавершённый этап с датой/версией набора.

## Чего в этом списке намеренно нет

Для текущих версий не создавать достижения за настоящее IPTV multicast/IGMP, PoE-питание телефонов, IMS/VoLTE, SIP-транки, внешние телефонные номера, SRTP/TLS Media, полноценный рекурсивный автокрафт AE2, работающие FTP/SNMP-службы, настоящие Cisco IOS и точное воспроизведение протокольных таймеров. Эти функции нельзя требовать как уже реализованные. Если они появятся в будущих версиях, добавить новую ветку или явное условие версии/возможности.

Ресурспак не нужен для прохождения. Не требовать покупки лицензии, просмотра конкретного YouTube-ролика, регистрации на внешнем сайте, отправки персональных данных или публикации скриншота преподавателю. Для теста видео подходит любой доступный разрешённый источник, который поддерживает текущий плеер.

## Какие события понадобятся будущему аддону

Это план инструментирования, не уже существующее API:

- Завершение крафта и плавки, корректная добыча руды, установка/снятие оборудования, карточек и модулей.
- Изменение кабеля, успешное подключение/отключение, поступление FE и переход устройства в рабочее состояние.
- Открытие консольной сессии, переход режима, принятие конфигурации, сохранение/чтение карты.
- Результат сетевой доставки с путём, VLAN, протоколом, инициатором и причиной отказа; отдельный результат восстановления после зарегистрированного сбоя.
- Изменения реальных таблиц коммутации/маршрутизации, DHCP-выдача, DNS-ответ и подтверждённый удалённый доступ.
- Журнал билетов Automation, фактическая вставка предметов/жидкости, срабатывание правил, результат шаблона, состояние охлаждения.
- Выпуск/отзыв SIM, регистрация абонента, используемая сота, назначенный IP и реальная передача через радио.
- Состояние спутниковой пары, регистрация модема, готовность выхода и результат браузерного запроса.
- Создание/изменение канала, состояние приставки, декодированный кадр и подтверждение звукового вывода; клиентские сообщения перепроверяются по активному серверному сеансу.
- Регистрация аппарата на АТС, установление/окончание звонка, счётчики принятых голосовых кадров обоих участников. Содержимое микрофона, записи разговоров, пароли и URL с секретами для достижения не сохраняются.

Где результат существует только на клиенте (реальный кадр, вывод звука), сервер проверяет активную разрешённую сессию и соответствие устройства/канала. Не считать произвольный клиентский пакет самостоятельным доказательством выполнения. При недоступном достоверном событии задание следует пометить как требующее доработки отслеживания, а не выдавать его по одному нажатию кнопки.

## Проверка при развитии дополнения

- Граф не содержит циклов, одинаковых ID и родителей отсутствующих веток.
- Загружается только основная ветка при одном NetLab; проверяются все допустимые сочетания дополнений.
- Импорт карты и демонстрационный стенд не выдают чужую историю обучения.
- Удаление/возвращение дополнения не ломает мир и не стирает отметки игрока.
- У каждой доступной карточки есть понятная следующая цель и ссылка на существующую статью книги.
- Согласованы награды, доступность сервисов и политика общего финала на сервере.
