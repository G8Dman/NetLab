# NetLab Mobile 0.3.1-alpha

Для NetLab 0.21.0-alpha+, Minecraft 1.21.1, NeoForge 21.1.265 и Java 21.

## С чего начать

NetLab Mobile — отдельное дополнение к NetLab для Minecraft 1.21.1 / NeoForge. Оборудование находится во вкладке NetLab Mobile. Оборудование, мобильные платы, RF-кабель и заготовки SIM имеют рецепты верстака. Сборщик базового мода по-прежнему производит свои платы расширения.

Для получения набора в creative/с правом оператора: /netlab mobile kit. Команда выдаёт оборудование и пустые SIM, ничего не строит. Дополнительно возьми шкаф, питание, оптику, Ethernet, карты памяти и терминал из основного мода.

Минимальная схема:
Антенна → 2 RF-кабеля → RRU → оптика → плата FRONTHAUL в BBU → Ethernet → коммутатор → ядро EPC.
SIM-станок → Ethernet → тот же коммутатор → EPC.
Телефон или модем ПК связывается с антенной по радио.

Все адреса и пакеты существуют внутри мира Minecraft. Выход в настоящий Интернет добавляет совместно установленный Sputnik с настроенным интернет-шлюзом. Это учебная модель архитектуры LTE, а не эмулятор настоящей базовой станции.

## Антенна, высота и радиосигнал

Антенна занимает две клетки по высоте; верхняя клетка должна быть свободна. При клике по боковой грани стены крепления прилегают к стене, сектор направлен наружу. RF-порты остаются снизу. При разрушении любой половины удаляются обе части и выдаётся один предмет. Старые антенны достраиваются вверх при загрузке, если над ними воздух; при занятой верхней клетке освободи место и нажми ПКМ по нижней части либо переустанови антенну.

Башню игрок строит самостоятельно из любых блоков. Поставь секторную антенну минимум на 12 блоков выше окружающей земли. Высота измеряется по медиане поверхности в восьми точках вокруг антенны, а не по абсолютной координате Y.

Поставь RRU рядом с антенной. Два RF-порта антенны соедини с RF0/0 и RF0/1 одного RRU двумя антенными RF-кабелями. Антенна и RRU должны находиться в пределах 8 блоков друг от друга. Fronthaul0/0 RRU соединяется обычным оптическим кабелем с Fronthaul0/0..2 BBU; это отдельный транспорт радиотракта, Ethernet сюда не подключается.

Сектор смотрит в сторону лицевой поверхности антенны. Азимут можно переопределить в Console RRU: mobile azimuth 0 — юг, 90 — запад, 180 — север, 270 — восток; auto — по повороту блока. mobile tilt 6 задаёт наклон вниз.

По умолчанию: band 20, канал 6300, дальность 512 блоков. mobile band 3 даёт более сильное затухание. mobile range 64..1024 ограничивает покрытие. Дальность не гарантирует хороший приём: учитываются расстояние, сектор, наклон, препятствия, высота и помехи от других станций на том же диапазоне и канале.

Полоски показывают уровень сигнала, а статус регистрации — право доступа. Видимый сигнал без SIM ещё не означает доступ к сети.

## Шкаф, платы, питание и память

Передние порты обозначены ETH0 (Ethernet, светлая рамка), FH0..2 (оптический fronthaul, оранжевый), RF0/RF1 (коаксиальные RF-разъёмы с золотистыми кольцами) и CON (консоль, голубой). FE находится сзади. Полные имена интерфейсов показываются очками при наведении. Порты отрисованы перед панелью корпуса; точка подключения и зона выбора совпадают с рисунком. После установки NL-MOB-FRONTHAUL в BBU появляются три отдельных подписанных разъёма.

BBU и ядро EPC можно установить в две штатные ячейки серверного шкафа и снять отвёрткой Shift+ПКМ. RRU крепится на построенной игроком башне, SIM-станок ставится отдельно.

BBU требует три платы: NL-MOB-CONTROL → control0; NL-MOB-BASEBAND → baseband0; NL-MOB-FRONTHAUL → fronthaul0. Последняя добавляет три оптических порта. Установка и снятие плат — при Power OFF через физическую панель. У ядра EPC эти платы не требуются.

BBU, EPC, RRU и станок питаются от FE через задний вход: энергошкаф → IN блока питания шкафа → OUT → устройство. Расход: BBU 12, EPC 16, RRU 8, станок 4 FE/тик. Антенна пассивная, ей питание не нужно.

Для сохранения настроек инфраструктуры вставь карту памяти CISCO во вкладке «Память» физической панели при выключенном питании. Пустая карта сразу включает автозапись. Без неё IP, пароль оператора и база абонентов временные и пропадут после перезагрузки устройства/мира. Настройки сохраняются при закрытии терминала.

Для явного сохранения после enable используй write memory (сокращения wr и wr mem) либо copy running-config startup-config. Из режима настройки работает do write memory. Прежняя команда memory write оставлена как совместимый псевдоним; memory read по-прежнему читает карту. Без карты сохранение выдаёт понятную ошибку.

Мобильные настройки, пароль и абоненты EPC сохраняются на карте. Реальные SIM внутри станка, его незавершённый выпуск и SIM в телефоне/ноутбуке хранятся отдельно и не копируются картой настройки.

У каждого активного инфраструктурного блока ограниченно поддерживаются загруженными соседние чанки: максимум 16 узлов по 3×3 чанка на измерение. Вся область радиопокрытия не загружается. Длинную проводную транспортную сеть также нужно держать загруженной. mobile keep-loaded off отключает загрузку данного узла.

## Настройка EPC и транспортной LAN

Пример отдельной LAN 192.168.77.0/24. Соедини EPC, BBU и SIM-станок с коммутатором Ethernet-кабелями. Проверь VLAN, порты и питание. Эти IP должны быть свободны.

Подключи терминал к Console EPC и введи:
enable
configure terminal
interface gi0/0
ip address 192.168.77.2 255.255.255.0
no shutdown
exit
mobile password operator123
mobile operator 00101 Учебная сеть
mobile pool 10.64.0.1
mobile apn netlab
end
write memory

operator123 — только пример; выбери свой пароль из 8..64 символов. PLMN — 5 или 6 цифр. Настрой PLMN, APN и пул до выпуска SIM. Пул — /24, первые выдаваемые IP .10..250. Шлюз не должен пересекаться с транспортной LAN.

BBU настраивается через Console так же: IP 192.168.77.4 /24 на gi0/0, no shutdown; в configure terminal: mobile core 192.168.77.2. Установи три платы BBU и оптику к RRU.

Важно: проверь административное состояние портов BBU, особенно в старом сохранении или после чтения карты. Подключённого оптического кабеля недостаточно, если порт находится в shutdown. Включи каждый реально используемый порт. Новая плата включает fronthaul по умолчанию, но сохранённый shutdown сохраняется. Для Fronthaul0/0:

```text
enable
configure terminal
interface Fronthaul0/0
no shutdown
end
write memory
```

Если кабель вставлен в FH1 или FH2, выбери Fronthaul0/1 или Fronthaul0/2 соответственно. На стороне RRU также проверь Fronthaul0/0, RF0/0 и RF0/1: они должны быть no shutdown. IP на них не нужен. show mobile показывает административное состояние и наличие кабеля, show ip interface brief — состояние интерфейсов.

SIM-станок: IP 192.168.77.3 /24 на gi0/0, no shutdown; mobile core 192.168.77.2. Между этими тремя узлами в одной подсети отдельный шлюз не нужен.

В RRU не назначай IP на RF/Fronthaul: его параметры меняются mobile-командами через Console. ПК с Console подключается консольным кабелем RS232; можно использовать портативный терминал.

Проверь ping между BBU, станком и EPC перед выпуском SIM.

## Выпуск и активация SIM

1. Настрой EPC, BBU и транспортную LAN. Станок и EPC должны иметь питание, активные Ethernet-порты, IP и возможность доставить ответ друг другу. Поставь карты памяти CISCO заранее.
2. ПКМ по SIM-станку. Введи пароль EPC и нажми «Авторизовать станок». Станок выполняет сетевой обмен с ядром. Пароль в панели скрыт и после отправки очищается.
3. Положи пустую SIM в инвентарь игрока и нажми «Вставить пустую SIM». В станок помещается одна карта; она действительно расходуется при выпуске.
4. Нажми «Выпустить / повторить запрос». Дождись сетевого обмена, регистрации и активации в EPC. Потом нажми «Забрать готовую SIM».

Те же операции через Console станка после enable:
mobile pair ПАРОЛЬ_EPC
mobile issue Имя SIM

Если связь оборвалась, не добавляй новую карту: восстанови сеть и повтори выпуск. Станок хранит тот же UUID незавершённой SIM и не создаёт второй экземпляр при повторном ответе. Выход недоступен до подтверждения активации.

show subscribers в Console EPC показывает UUID, имя, активность и выданный IP. configure terminal → mobile revoke UUID отзывает SIM. Один UUID не может одновременно зарегистрироваться в двух устройствах.

Смена пароля EPC требует повторной авторизации станков. SIM привязаны к физической идентичности EPC: перенос самого блока сохраняет её, копирование конфигурации на другое ядро не создаёт ту же идентичность. Для нового ядра выпускай новые SIM. Максимум 256 записей SIM; одновременно доступно до 241 адреса стандартного пула.

## Телефон, ПК и ноутбук

Cisco Pocket — телефон Cisco с индикатором сети и приложениями через устанавливаемые модули. Возьми телефон в руку, нажми ПКМ и вставь активную SIM из инвентаря. На экране есть полоски, RSRP, SINR, расстояние, найденные станции и статус регистрации. Регистрация поддерживается, пока телефон в одной из рук; после убирания сессия истекает. Приложения и передача пакетов описаны в статье «Cisco Pocket: модули и приложения».

Для ПК и ноутбука:
1. Физическая панель → Power OFF → модули: CISCO-LTE-MODEM в mobile0. Он не занимает Wi-Fi, USB-RS232 или слот автоматики.
2. В Desktop появится «Мобильная сеть». Пока ПК выключен, открой приложение и вставь активную SIM из инвентаря.
3. Включи ПК через физическую панель. Снова открой «Мобильная сеть» → «Подключиться».
4. После регистрации EPC выдаст IP из 10.64.0.0/24 и шлюз 10.64.0.1 на Cellular0. Затем доступны обычные команды и сетевые приложения NetLab.

Подключение к мобильной сети временно выбирает Cellular0 вместо Ethernet/Wi-Fi. Кнопка «Отключиться» возвращает предыдущий интерфейс и профиль Wi-Fi. Смена SIM — при Power OFF. Нельзя снять модем с установленной SIM: сначала извлеки карту в приложении.

Ноутбук сохраняет модем, SIM и настройки во встроенной памяти и в предмете блока при разрушении. Телефон также сохраняет установленную SIM. Каждый телефон или ПК требует отдельную SIM.

## Пакеты, скорость, маршруты и VPN

После регистрации трафик ПК действительно проходит цепочку: радио → антенна → RF → RRU → оптический fronthaul → BBU → проводная сеть → EPC → адрес назначения. На обратном пути цепочка разворачивается. Обрыв кабеля, питание, отзыв SIM или ошибка маршрута прерывают доставку.

Потолок сектора: 5 Мбит/с вниз и 1 Мбит/с вверх. Это общая очередь направления, а не отдельные 5/1 для каждого абонента. Плохое качество сигнала снижает доступную скорость; радиопереход добавляет 8 мс. Существующие контроллеры скорости замедляют проводной транспорт. Штатный такт мира ограничивает точность исполнения таймеров, реальные пакеты за пределы Minecraft не отправляются.

Очки показывают LTE-AIR, RF-IQ, FRONTHAUL-IQ и проводные UDP-пакеты туннеля BBU↔EPC. Для замедленного наблюдения используй контроллер трафика NetLab. На эфире Ethernet ARP нет: абоненты используют EPC как шлюз, включая связь между двумя мобильными абонентами.

В одном только транспортном сегменте BBU↔EPC шлюз не нужен. Но проводной сервер, к которому обращается мобильный ПК, должен иметь обратный маршрут в 10.64.0.0/24. В примере его gateway можно поставить 192.168.77.2, если других маршрутов не требуется. Если сервер использует обычный роутер 192.168.77.1, на роутере добавь: ip route 10.64.0.0 255.255.255.0 192.168.77.2. На EPC настрой ip default-gateway 192.168.77.1 для внешних подсетей.

SIM-аутентификация использует challenge/response. Радиоданные UE↔BBU защищаются отдельными AES-GCM ключами сеанса с защитой от повтора. Это учебная защита, не реализация LTE-AKA/PDCP. Она не шифрует проводной BBU↔EPC и не заменяет VPN: VPN настраивается на маршрутизаторах Cisco, как раньше. Автоматика и передача предметов сохраняют существующую сетевую модель.

## Справочник mobile-команд

Команды NetLab Mobile собственные, они не являются CLI Huawei, ИРТЕЯ или Cisco IOS.

mobile panel — открыть панель физического устройства / SIM-станка из терминала; права доступа сохраняются.
show mobile — IP, EPC, оператор, пул, параметры радио, состояние памяти.
show subscribers — только EPC: UUID, имя, активность и IP зарегистрированных SIM, без секретов.
help или ? — синтаксис команд. Tab дополняет префиксы.

Обычная настройка: enable → configure terminal; interface gi0/0 → ip address IP MASK → no shutdown; exit/end; ip default-gateway IP. EPC также поддерживает статические ip route NETWORK MASK NEXT_HOP. write memory, memory read и show memory работают через основной мод.

В configure terminal:
mobile password ПАРОЛЬ — EPC; новый пароль авторизации станков, 8..64 символов.
mobile operator PLMN ИМЯ — EPC; PLMN из 5..6 цифр, имя оператора. После выпуска SIM менять PLMN нельзя.
mobile pool IP — EPC; IP шлюза абонентской сети /24 до выпуска SIM, например 10.64.0.1.
mobile apn ИМЯ — EPC; APN записывается в новые SIM, по умолчанию netlab. Смена APN отключит старые SIM.
mobile core IP — BBU/станок; транспортный IP ядра EPC.
mobile revoke UUID — EPC; отключить конкретную SIM.
mobile radio on|off — RRU; включить или выключить передатчик.
mobile band 3|20 — RRU; диапазон распространения.
mobile channel N — RRU; канал 0..65535; одинаковые band/channel создают помехи.
mobile azimuth auto|0..359 — RRU; направление сектора, auto берёт поворот антенны.
mobile tilt 0..20 — RRU; наклон вниз в градусах.
mobile range 64..1024 — RRU; предельная дальность в блоках.
mobile keep-loaded on|off — BBU/EPC/RRU/станок; ограниченная поддержка загрузки чанков.

В enable или configure terminal на станке:
mobile pair ПАРОЛЬ — авторизация в ядре с сетевым подтверждением.
mobile issue [ИМЯ] — выпуск/повтор сохранённой операции; нужна вставленная пустая SIM и свободный выход.

Секреты не выводятся show-командами и не передаются в общих обновлениях блоков клиентам.

## Если базовая станция не работает

Проверь по цепочке: питание EPC/BBU/RRU; три платы BBU; активный Fronthaul на обеих сторонах оптики; два RF-кабеля от одного RRU к одной антенне (до 8 блоков); высота антенны не менее 12 блоков над окружающей поверхностью; mobile radio on; IP и mobile core BBU; ping BBU↔EPC; активная SIM своего EPC и совпадающий APN. Неподключённые антенны покрытия не дают — каждой нужен отдельный RRU и оптика к BBU.

## Граница проверки

Сборка, чистая модель сети и отдельная проверка реестров/NBT/пакетных кодеков выполняются без клиента, сервера, мира и GameTest. Это не проверка поведения игрового клиента. Не реализованы настоящий LTE PHY/MAC, 3GPP ASN.1/S1AP, EPS-AKA, PDCP, VoLTE, звонки, SMS и внешний Интернет. По транспортной сети учтён учебный UDP bearer на порту 2152; это не двоично совместимый GTP-U. Служебные запросы регистрации/выпуска используют общий планировщик ApplicationTransport. Оценка сигнала предназначена для игры, не для проектирования реальной радиосети.

## Cisco Pocket: модули и приложения

Cisco Pocket поддерживает четыре независимых модуля. Диагностика и пакеты добавляются NetLab Mobile, браузер — NetLab Sputnik, управление мультиинтерфейсами — NetLab Automation. Предметы находятся во вкладках своих дополнений и «NetLab модули».

Телефон → Модули → Установить: модуль расходуется из инвентаря. Извлечь возвращает предмет. SIM, модули и привязка сохраняются в самом телефоне. Для работы приложений держи телефон в руке и дождись регистрации SIM. IP и шлюз выдаёт EPC.

Модуль диагностики: вкладка Сеть, игровой IP назначения, Ping либо UDP/TCP, порт и данные → Отправить пакет. Очки показывают реальный путь пакета через антенну, RRU, BBU и EPC. Общие очереди сектора и настройки скорости сохраняются. Радиоданные защищены AES-GCM; проводную защиту обеспечивает VPN на маршрутизаторах.

Модуль браузера принадлежит Sputnik. Установи оба дополнения, Rinku 3.0.4 на клиенте и браузерный модуль телефона. Приложения → Браузер Sputnik. Требуется маршрут от EPC до работающего интернет-шлюза провайдера и обратно; инструкции находятся в разделе Sputnik.

Модуль автоматики сначала привязывается: возьми модуль в руку и нажми ПКМ по своему настроенному серверу, в том числе по нужной ячейке шкафа. На сервере должны быть IP и management password. Затем установи модуль в телефон. Приложения → Управление мультиинтерфейсами; адрес привязанного сервера подставляется, пароль вводится вручную. Можно отправлять предметы и жидкости и использовать прежние правила/рецепты. Сервер показывает свою локальную сеть, а телефон может подключаться через EPC и маршрутизаторы. Модуль не даёт доступ к другому серверу с тем же IP: проверяется физический ID и измерение. После замены сервера или смены его IP перепривяжи модуль.

Извлечение модуля или SIM, отзыв SIM и потеря радиосвязи прекращают новые запросы. Привязанный модуль можно извлечь и перенести в другой телефон; пароль сервера на модуле не хранится.


## Терминальный модуль телефона

Создай модуль терминала Cisco Pocket и установи его через телефон → «Модули». Затем возьми телефон в руку и нажми ПКМ непосредственно по голубому Console устройства. RS232 компьютера и Ethernet не подходят. SIM, мобильная сеть и интернет для такого подключения не требуются.

Работают команды, ? и Tab общей консоли. Телефон хранит текст и историю команд трёх последних физических устройств. При повторном открытии того же устройства история возвращается; стрелки вверх/вниз выбирают команды. Открытие четвёртого устройства удаляет историю самого давно открывавшегося. Другое устройство на том же месте не получает чужую историю.

История остаётся в самом телефоне после закрытия меню, переноса и сохранения мира. Пароли и команды с ключами не записываются в повтор команд. Авторизованная сессия не сохраняется: при новом подключении снова действуют правила входа устройства. Извлечение модуля прекращает доступ, но не стирает историю. Обычный портативный терминал по-прежнему не хранит историю.

Оборудование, платы, кабели и заготовки SIM теперь имеют рецепты верстака. Зарегистрированная SIM выпускается станком после настройки связи с EPC.
