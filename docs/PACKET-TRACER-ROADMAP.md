# Что добавить из Packet Tracer в NetLab

Сравнение от 7 ноября 2026 года: локальная установка Cisco Packet Tracer
9.0.1 и исходники NetLab 0.19.0-alpha с дополнениями Automation 0.7.0,
Mobile 0.2.0 и Sputnik 0.2.0.

Основа исследования — поставляемая с Packet Tracer HTML-справка, названия
лабораторных примеров и обработчики/модели NetLab. Packet Tracer и Minecraft
для проверки поведения не запускались. Поэтому это план развития,
а не протокол сравнения вывода команд двух запущенных программ.
Команды ниже предлагаются для будущей реализации: наличие строки в плане
не означает, что её уже принимает NetLab. Точный синтаксис зависит от шасси
и версии программного обеспечения.

## Что уже есть и что важно дополнить

В NetLab уже реализованы физические модули и кабели, VLAN/trunk, модель STP,
EtherChannel, port security, DHCP snooping, ACL/NAT, DHCP/relay, DNS-записи,
базовые RIP/OSPF/EIGRP, часть IPv6, Wi-Fi, удалённый CLI и собственный VPN.
Это разные уровни детализации: наличие команды не означает полную модель
протокола с таймерами и служебными пакетами.

Подтверждённые ограничения текущего кода:

- `PCCommands` принимает FTP/SNMP/netstat, но прямо сообщает, что соответствующие
  операции или таблица транспортных сессий не реализованы.
- TFTP уже копирует конфигурации после проверки достижимости UDP/69; данные
  записываются в модель flash другого устройства. Нужен отдельный сервис
  с файлами, включением/выключением и передачей по сети, а не вторая команда copy.
- `RoutingModel` рассчитывает сходимость аналитически; его комментарий явно
  исключает полный обмен Hello/LSA/DUAL и redistribution между протоколами.
- Шасси 3560/3650 имеются, но полноценного поведения L3-коммутатора с
  `ip routing` и routed ports нет.
- Wi-Fi использует open/WPA2-PSK; WLC, CAPWAP и корпоративной AAA нет.
- `StudyScreen` даёт скорость просмотра и паузу, но не инспектор заголовков
  и объяснение обработки пакета по уровням OSI.
- Для оптики проверяется общий тип среды fiber. Детальной совместимости
  SM/MM, оптических бюджетов и длины волны нет.

## Новое оборудование и функциональные роли

| Приоритет | Устройство или роль | Что должно измениться в работе сети | Учебный сценарий |
|---|---|---|---|
| 1 | Сервер сетевых служб, аналог Server-PT | Независимые DNS, DHCP, TFTP, FTP, NTP, Syslog, AAA, внутренний HTTP; доступ проверяется по маршруту, ACL и состоянию сервиса | Настроить сеть с именами, временем, журналами и резервными копиями |
| 1 | Анализатор пакетов и приложение на ПК | Просмотр захвата с порта SPAN/встроенного перехватчика; заголовки, время, направление и причина отброса | Найти ошибку VLAN, ACL, шлюза или DHCP |
| 1 | Полноценные L3-профили существующих 3560/3650 | Маршрутизация через SVI и routed ports; включение/выключение ip routing | Связать VLAN без отдельного router-on-a-stick |
| 2 | Контроллер Wi-Fi WLC + lightweight AP | Регистрация AP, несколько WLAN, SSID→VLAN, группы AP, централизованная аутентификация | Отдельные сети сотрудников и гостей на нескольких точках |
| 2 | Межсетевой экран, аналог ASA/ISA3000 | Stateful-таблица соединений, зоны/интерфейсы, NAT, инспекция, журнал отказов | Разделить LAN, серверы и внешнюю сеть |
| 2 | Контроллер управления сетью | Схема по обнаружению устройств, инвентаризация, состояние портов, резервные копии и применение шаблонов с проверкой прав | Управлять учебным кампусом с одного ПК |
| 3 | IP-телефон и PoE | Телефонные номера и сигнализация вызова; питание через Ethernet с бюджетом мощности | Проверить voice VLAN и влияние перегрузки на звонок |
| 3 | PLC, HMI, сервер истории | Регистры/сигналы Modbus TCP, правила PLC, панель оператора и графики | Управлять печью, уровнем бака, редстоуном и оборудованием других модов |

Сервер сетевых служб можно сделать новым стоечным устройством с платами
сервисов. Объединять его с сервером Automation необязательно: это разные
роли, хотя обе могут использовать общий механизм питания, памяти и охлаждения.
Проверка доступности порта сама по себе не должна считаться успешной работой
сервиса: нужен реальный для модели запрос и ответ.

Уже имеющийся перехватчик Automation разумно расширить общим API захвата,
чтобы не создавать второй независимый механизм наблюдения. Возможность
наблюдать содержимое должна зависеть от точки захвата и шифрования.

## Команды и их обязательный эффект

| Группа | Примеры будущих команд | Как проверять реализацию |
|---|---|---|
| Мониторинг | `logging host IP`, `logging trap LEVEL`, `service timestamps log datetime msec`, `ntp server IP`, `show ntp associations` | Отключение интерфейса создаёт сообщение на достижимом Syslog-сервере; синхронизация зависит от ответа NTP |
| SNMP | `snmp-server community NAME ro`, `snmpget`, `snmpgetbulk` | Чтение ограниченного набора MIB/OID: имя, uptime, состояние и счётчики интерфейсов; проверка community, маршрута и ACL |
| AAA | `aaa new-model`, `aaa authentication login default group radius local`, настройка RADIUS/TACACS+ | Разрешение/отказ от сервера меняет вход; local fallback действует по правилам выбранного метода |
| HSRP | `standby 1 ip IP`, `standby 1 priority 110`, `standby 1 preempt`, `show standby brief` | Два устройства обслуживают виртуальные IP/MAC; отключение active вызывает переход после таймера |
| BGP | `router bgp ASN`, `neighbor IP remote-as ASN`, `network PREFIX mask MASK`, `show ip bgp summary` | Сессия устанавливается при достижимости и согласованных параметрах; отзыв маршрута меняет доставку |
| QoS | `class-map`, `policy-map`, `service-policy output NAME`, `show policy-map interface` | При перегрузке разные классы получают различную задержку/потери; у правил есть счётчики |
| L3-коммутация | `ip routing`, `no switchport`, существующий `interface vlan N` с L3-поведением | Пакеты переходят между VLAN только через разрешённые L3-интерфейсы и маршруты |
| Защита LAN | `ip arp inspection vlan N`, `ip arp inspection trust`, `show ip arp inspection` | Поддельный ARP отбрасывается по привязкам/правилам, законный проходит; DHCP snooping используется повторно |
| IPv6 | OSPFv3, DHCPv6, настройка RA/SLAAC, IPv6 ACL и диагностический вывод | Клиент действительно получает параметры и маршрут, фильтрация меняет доставку IPv6 |

HSRP, BGP, QoS, AAA и SNMP представлены в деревьях/службах Packet Tracer.
DAI дополнительно подтверждается локальным примером `03 Cybersecurity/DAI/dai_sample.pkt`.
L3-поведение нужно сверять с документацией именно выбранной платформы Cisco:
общая справка PT не перечисляет исчерпывающе все различия между моделями.

Существующий контроллер скорости NetLab решает другую задачу, чем QoS:
он позволяет администратору менять учебное время доставки. QoS должен
обрабатывать конкуренцию классов в очереди конкретного интерфейса.

Для каждой новой группы нужны рабочий обмен, отказные сценарии, корректные
`show`, `no`, сокращения, `?`, Tab, running/startup-config и сохранение на карте.
Новая строка CLI без сетевого эффекта не завершает функцию.

## Что улучшить в моделировании

1. **Инспектор пакета в очках.** По выбранному пакету показать входной и выходной
   порт, MAC/IP, VLAN, TTL, протокол/порты, длину, очередь, время и решение
   устройства. Например: «ACL 101 deny», «VLAN 10 не разрешён на trunk»,
   «нет ARP-ответа». Отдельно показывать данные до и после NAT/инкапсуляции.
2. **Служебные пакеты и сходимость.** Добавлять Hello/LSA, BPDU и LACP поэтапно,
   с состояниями и таймерами. Сначала ограниченный OSPFv2 и RSTP; полные DUAL,
   все типы областей и перераспределение маршрутов — последующие этапы.
3. **Физика Ethernet и оптики.** Учитывать совместимость SFP, скорость, тип
   волокна и учебный предел длины; затем оптический бюджет. Добавить PoE,
   согласование duplex и диагностические счётчики ошибок. Параметры дальности
   для Minecraft должны быть явно масштабированы и настраиваться.
4. **Транспорт.** Уйти от наличия «TCP-пакета» как единственного доказательства
   TCP-соединения: состояния сеансов, handshake, таймауты, повторная передача,
   таблица `netstat` и отслеживание stateful firewall.
5. **Конфигурация VPN.** Текущий `crypto netlab-vpn` — собственная функция.
   Cisco-подобные IKE/IPsec-команды требуют модели согласования политик,
   SA, сроков жизни и ошибок; сначала согласованный ограниченный набор,
   сохраняющий фактическую защиту передаваемых данных.

## Промышленная часть для Automation

Packet Tracer 9 добавляет промышленное направление: PLC, HMI, Data Historian,
промышленные коммутаторы/маршрутизаторы и протоколы Modbus, OPC-UA,
PROFINET, CIP и IEC 61850. Это полезная основа отдельного этапа Automation.

Начать стоит с **Modbus TCP + PLC + HMI**:

- Мультиинтерфейс преобразует доступные возможности блока в разрешённые
  регистры и сигналы; список поддержанных операций виден игроку.
- PLC читает температуру/уровень/состояние, выполняет ограниченную логику
  и отправляет команды. HMI отображает состояние и позволяет оператору
  изменять разрешённые параметры.
- Historian на сервере хранит ограниченный журнал измерений с графиками.
- Доставка идёт через обычные VLAN, маршруты, ACL и VPN. При обрыве сети
  PLC переходит в заданное безопасное состояние, а не исполняет удалённые
  команды через недоступный канал.

Modbus не должен заменять существующий журнал владения предметами и жидкостями:
это управление и телеметрия, а перенос ресурсов остаётся механизмом Automation.
Ladder Logic можно добавить после устойчивой модели сигналов. Все промышленные
протоколы сразу для первой версии не нужны.

## Учебные задания

По образцу Activity Wizard добавить задания с исходным стендом, условиями
успеха и проверкой результата: доступность сервиса, распределение VLAN,
отказоустойчивость, запрет нежелательного трафика. Оценивать работающую сеть,
а не совпадение конфигурации с одной заготовкой: правильных решений бывает
несколько. Учителю нужны подсказки и создание неисправностей; для проверки
ACL необходимы как разрешённые, так и запрещённые пробы.

## Порядок реализации

1. Инспектор пакетов и сервер Syslog/NTP; затем DNS/TFTP/FTP/HTTP и SNMP.
2. Полноценная L3-коммутация и HSRP, затем расширение протокольных таймеров.
3. AAA и WLC, после них stateful firewall и QoS на общей модели сеансов/очередей.
4. BGP для сетей нескольких игроков/операторов и расширение IPv6.
5. PLC/Modbus/HMI для Automation, затем телефония и более сложная OT.

Новые C8200, IR1101/IR8340, IE3400 и другие корпуса имеют смысл после появления
характерных функций. Добавление одного внешнего вида даёт меньше пользы
для обучения, чем рабочая диагностика уже имеющейся сети.
