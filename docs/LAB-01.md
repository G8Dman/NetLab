# Лабораторная 1: две подсети и маршрутизатор

Поставь ПК-A, коммутатор, маршрутизатор и ПК-B. Соедини:

```
ПК-A eth0 ── Switch g0/0
             Switch g0/1 ── Router g0/0
                            Router g0/1 ── ПК-B eth0
```

Каждую команду вводи отдельно через Enter. Открывай терминал пустой рукой.

На ПК-A:

```
ipconfig 192.168.10.2 255.255.255.0 192.168.10.1
```

На ПК-B:

```
ipconfig 192.168.20.2 255.255.255.0 192.168.20.1
```

На маршрутизаторе:

```
enable
configure terminal
hostname R1
interface g0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit
interface g0/1
ip address 192.168.20.1 255.255.255.0
no shutdown
end
show ip interface brief
show ip route
```

На ПК-A:

```
ping 192.168.20.2
```

Должен появиться ответ с путём PC → Switch → R1 → PC и сообщением о проверенном обратном маршруте. Статические маршруты здесь не нужны: обе подсети непосредственно подключены к R1.

## Найди неисправность

1. На R1 выключи второй интерфейс (`conf t`, `int g0/1`, `shutdown`, `end`). Проверь ping. Верни `no shutdown`.
2. На ПК-B задай адрес без шлюза: `ipconfig 192.168.20.2 255.255.255.0`. Ping с ПК-A должен сообщить, что запрос дошёл, но ответ не смог вернуться. Верни шлюз.
3. Отключи один из кабелей через Shift + ПКМ предметом кабеля. Объясни, почему доступность интерфейса сама по себе не гарантирует связь.
4. Сохрани мир, выйди и зайди снова. Повтори ping и `show running-config`.

Дополнительные команды для сети из двух маршрутизаторов:

```
ip route 172.16.0.0 255.255.255.0 10.0.0.2
ip route 0.0.0.0 0.0.0.0 10.0.0.2
```

Они вводятся в режиме `(config)#`. Указывай следующий узел, доступный через непосредственно подключённую подсеть. Обратный маршрут также должен существовать.
