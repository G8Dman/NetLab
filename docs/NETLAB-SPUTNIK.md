# NetLab Sputnik: настройка по устройствам

Minecraft 1.21.1, NeoForge 21.1.265, Java 21. Для браузера на клиенте нужен Rinku 3.0.4. Sputnik добавляет браузер для ПК/ноутбука и браузерный модуль для телефона NetLab Mobile. Для самой спутниковой сети Mobile и Automation не обязательны.

## 1. Как устроен стенд

```text
Ноутбук ─ Ethernet ─ VSAT-модем ─ TX/RX ─ малая тарелка
                                      ⇅ GEO-1 ⇅
Интернет-шлюз ─ Ethernet ─ HUB ─ TX/RX ─ BUC/LNB ─ RF TX/RX ─ большая тарелка
```

HUB — центральное устройство провайдера. Оно регистрирует модемы и маршрутизирует их трафик. Интернет-шлюз — отдельный блок, выпускающий браузерные подключения к настоящим сайтам через интернет Minecraft-сервера. BUC/LNB — наружный радиоблок между HUB и большой тарелкой; IP на нём не нужен.

Все IP в этой инструкции существуют внутри Minecraft. IP сайта вручную ни одному блоку не назначается. В одиночной игре настоящий выход использует интернет твоего ПК, на выделенном сервере — интернет сервера.

## 2. Сначала питание, платы и память

На HUB, VSAT-модеме, интернет-шлюзе и BUC/LNB при Power OFF вставь по пустой карте CISCO через «Оборудование / питание / модули / память». Затем включи питание. Антеннам отдельная карта не нужна; у ноутбука и телефона память встроена. Пустая карта включает автозапись. После ввода команд используй end → write memory. Карта с чужими настройками читается отдельно через memory read.

В HUB установи три платы: NL-SAT-CONTROL в control0, NL-SAT-TX в tx0, NL-SAT-RX в rx0. У модема, BUC/LNB и интернет-шлюза эти платы не требуются.

Задний FE-вход каждого активного блока подключается к OUT блока питания шкафа. Расход: HUB — 16, интернет-шлюз — 8, BUC/LNB — 8, VSAT-модем — 6 FE/тик. Питание передаётся отдельным кабелем. Обе тарелки пассивные. Подключи питание ко всем четырём устройствам до настройки через Console.

Если устройство уже настроено, сначала проверь show memory и show ip interface brief. Сохранённый shutdown обновление автоматически не отменяет; включи нужный интерфейс командой no shutdown.

## 3. Подключить кабели и навести тарелки

Пары должны приходить в один и тот же блок:

```text
HUB LAN ↔ Ethernet ↔ LAN интернет-шлюза
HUB TX-IF ↔ коаксиал TX ↔ BUC/LNB TX-IF
HUB RX-IF ↔ коаксиал RX ↔ BUC/LNB RX-IF
BUC/LNB BUC-TX ↔ радиокабель TX ↔ TX большой тарелки
BUC/LNB LNB-RX ↔ радиокабель RX ↔ RX большой тарелки
VSAT-модем TX-IF ↔ коаксиал TX ↔ TX малой тарелки
VSAT-модем RX-IF ↔ коаксиал RX ↔ RX малой тарелки
VSAT-модем LAN ↔ Ethernet ↔ Ethernet ноутбука
```

Коаксиал допускает до 64 блоков, каждый радиокабель BUC/LNB↔большая тарелка — до 8. Считается вся длина кабеля с поворотами. Размещай BUC/LNB рядом с большой тарелкой. Satellite0/0 — внутренний интерфейс радиоканала; кабель в него не вставляется.

ПКМ по каждой тарелке: спутник GEO-1, азимут 180°, угол места 45°, кнопка «Навести». Оба терминала смотрят к северу и вверх. В первых 96 блоках этого направления не должно быть препятствий. Башня для Sputnik не обязательна. В измерении без неба связи нет.

Другие доступные направления: GEO-2 — 90° / 35°; GEO-3 — 270° / 55°. При смене спутника меняй выбор на обеих тарелках, HUB и модеме.

## 4. Адресный план: что куда вписывать

Пример использует три отдельные подсети. Проверь, что выбранные адреса свободны. Все маски — 255.255.255.0.

| Где | Интерфейс | IP | Шлюз / назначение |
|---|---|---|---|
| Ноутбук | Ethernet | 192.168.88.100 | Шлюз 192.168.88.1: отправляет внешний трафик модему |
| VSAT-модем | GigabitEthernet0/0, LAN | 192.168.88.1 | Шлюз 10.254.88.1: направляет трафик к HUB |
| VSAT-модем | Satellite0/0 | 10.254.88.2 | Адрес модема на радиоканале |
| HUB | Satellite0/0 | 10.254.88.1 | Вторая сторона того же радиоканала |
| HUB | GigabitEthernet0/0, LAN | 172.30.88.1 | Провайдерская сеть до интернет-шлюза |
| Интернет-шлюз | GigabitEthernet0/0, LAN | 172.30.88.2 | Шлюз 172.30.88.1: обратные ответы идут через HUB |
| BUC/LNB, тарелки | — | Не назначается | Работают с радиосигналом |

Адрес 10.254.88.1 одинаково пишется на Satellite0/0 HUB и в ip default-gateway модема. 10.253.88.1 — уже другая подсеть и разорвёт маршрут.

Шлюз ноутбука 192.168.88.1 и поле «Шлюз провайдера» в браузере 172.30.88.2 имеют разные назначения. Первый — ближайший маршрутизатор, второй — конкретный блок с настоящим интернет-выходом.

## 5. Console BUC/LNB: включить четыре радиопорта

Команды вводятся в Console самого BUC/LNB портативным терминалом или через RS232 ноутбука. IP, шлюз и UUID абонента на BUC/LNB не вводятся.

```text
enable
configure terminal
interface TX-IF
no shutdown
exit
interface RX-IF
no shutdown
exit
interface BUC-TX
no shutdown
exit
interface LNB-RX
no shutdown
exit
sat enabled on
end
write memory
show ip interface brief
```

Должны быть видны TX-IF, RX-IF, BUC-TX, LNB-RX и Console. LAN у BUC/LNB нет. Если на корпусе появились только LAN/Console, обнови NetLab и Sputnik, полностью перезапусти игру и проверь профиль оборудования.

## 6. Console VSAT-модема: LAN, радио и ключ

Открой Console VSAT-модема возле малой тарелки. MySputnikKey2026 — пример ключа: замени его своим значением 8–64 символа без пробелов и используй то же значение на HUB.

```text
enable
configure terminal
hostname VSAT
interface GigabitEthernet0/0
ip address 192.168.88.1 255.255.255.0
no shutdown
exit
interface Satellite0/0
ip address 10.254.88.2 255.255.255.0
no shutdown
exit
interface TX-IF
no shutdown
exit
interface RX-IF
no shutdown
exit
ip default-gateway 10.254.88.1
sat network lab-sat
sat satellite GEO-1
sat frequencies 14200 12000
sat polarization H
sat key MySputnikKey2026
sat enabled on
end
write memory
show sputnik
```

Скопируй строку ID из show sputnik или кнопкой «Скопировать ID» в панели ЭТОГО МОДЕМА. Это уникальная физическая идентичность модема, не IP и не идентичность малой тарелки. После замены модема на новый нужно зарегистрировать новый ID на HUB. Пока HUB не настроен, OFFLINE ожидаем.

## 7. Console HUB: адреса, обратный маршрут и абонент

HUB устанавливается в ячейку шкафа. Проверь, что открыл именно его Console. В строке sat subscriber замени UUID_МОДЕМА на ID из шага 6, а пример ключа — на ключ модема.

```text
enable
configure terminal
hostname SAT_HUB
interface GigabitEthernet0/0
ip address 172.30.88.1 255.255.255.0
no shutdown
exit
interface Satellite0/0
ip address 10.254.88.1 255.255.255.0
no shutdown
exit
interface TX-IF
no shutdown
exit
interface RX-IF
no shutdown
exit
ip route 192.168.88.0 255.255.255.0 10.254.88.2
sat network lab-sat
sat satellite GEO-1
sat frequencies 14000 12200
sat polarization H
sat subscriber UUID_МОДЕМА MySputnikKey2026
sat enabled on
end
write memory
show subscribers
```

Маршрут 192.168.88.0/24 через 10.254.88.2 нужен для ответов к ноутбуку. Без него запрос может уйти, а ответ не вернётся. sat subscriber разрешает определённому модему подключаться с определённым ключом. Неверную запись удаляют в configure terminal: sat revoke UUID.

Частоты сторон специально разные: HUB TX/RX 14000/12200 МГц, модем 14200/12000 МГц. Учебный ретранслятор переводит несущие вниз на 2000 МГц. Имя сети lab-sat, спутник GEO-1 и поляризация H на HUB и модеме должны совпадать.

Проверь show sputnik на модеме: нужен LOCK. Сначала добейся LOCK, затем проверяй браузер.

## 8. Console интернет-шлюза: настоящий интернет-выход

Открой Console отдельного блока «Интернет-шлюз», обычно во второй ячейке шкафа рядом с HUB. У обоих должен быть один владелец.

```text
enable
configure terminal
hostname INTERNET
interface GigabitEthernet0/0
ip address 172.30.88.2 255.255.255.0
no shutdown
exit
ip default-gateway 172.30.88.1
sat hub 172.30.88.1
sat internet on
sat enabled on
end
write memory
```

ip default-gateway направляет обратные ответы к HUB. sat hub указывает LAN-адрес конкретного HUB провайдера, а не его Satellite0/0. sat internet on разрешает настоящий веб-выход. Дополнительно должен существовать рабочий зарегистрированный HUB↔VSAT радиотракт.

## 9. Ноутбук: Command Prompt и браузер

В ноутбуке открой Desktop → Command Prompt. Terminal предназначен для Console внешнего устройства, а эти команды настраивают сам ноутбук.

```text
ipconfig 192.168.88.100 255.255.255.0 192.168.88.1
ping 192.168.88.1
ping 10.254.88.1
ping 172.30.88.2
```

Первый ping проверяет Ethernet до модема, второй — радиоканал до HUB, третий — путь до интернет-шлюза и ответ. На Console интернет-шлюза дополнительно проверь ping 192.168.88.100.

После успешных ping: Desktop → «Браузер», поле «Шлюз провайдера» — 172.30.88.2, сайт — https://example.com. При ровно одном доступном интернет-шлюзе поле можно оставить пустым. Для начала проверяй простой сайт, затем более тяжёлые страницы.

Колонка подключается аудиокабелем AudioOut ноутбука → AudioIn колонки и отдельным FE. В браузере включи звук и сверни окно. Музыка продолжает работать; рядом с колонкой её слышат другие игроки. ПКМ по колонке меняет громкость и выключатель.

## 10. Браузер в телефоне через мобильную сеть

Телефон добавляет NetLab Mobile, браузерный модуль — NetLab Sputnik. Нужны оба дополнения и Rinku 3.0.4 на клиенте. Возьми «Модуль браузера Cisco Pocket» во вкладке Sputnik или «NetLab модули», открой телефон → «Модули» → установи браузерный модуль из инвентаря.

Вставь активную SIM своего EPC и дождись регистрации. Телефон автоматически получает мобильный IP и шлюз EPC. Держи телефон в руке. Открой «Приложения» → «Браузер Sputnik»; поле провайдерского шлюза — тот же доступный IP интернет-шлюза, например 172.30.88.2. Звук браузера телефона воспроизводится локально.

Каждый запрос проходит телефон → радио → антенна/RRU → BBU → EPC → настроенные проводные/спутниковые маршруты → интернет-шлюз. Потеря регистрации, извлечение SIM или модуля закрывает доступ. Одной установки браузерного модуля недостаточно: нужен маршрут туда и обратно.

Пример подключения уже работающей мобильной LAN 192.168.77.0/24 к абонентской LAN Sputnik 192.168.88.0/24: EPC = 192.168.77.2; маршрутизатор имеет Gi0/0 = 192.168.77.1 и Gi0/1 = 192.168.88.2; VSAT-модем = 192.168.88.1. BBU и SIM-станок остаются в своей мобильной LAN. Адреса должны быть свободны.

На Console маршрутизатора, после назначения IP его портам и no shutdown:

```text
enable
configure terminal
ip route 10.64.0.0 255.255.255.0 192.168.77.2
ip route 172.30.88.0 255.255.255.0 192.168.88.1
end
write memory
```

На Console EPC:

```text
enable
configure terminal
ip default-gateway 192.168.77.1
end
write memory
```

На Console VSAT-модема:

```text
enable
configure terminal
ip route 10.64.0.0 255.255.255.0 192.168.88.2
end
write memory
```

На Console HUB:

```text
enable
configure terminal
ip route 10.64.0.0 255.255.255.0 10.254.88.2
end
write memory
```

Эти обратные маршруты возвращают ответы из провайдерской сети в мобильный пул 10.64.0.0/24. Если у EPC выбран другой пул, подставь его сеть во все три маршрута. В телефоне через модуль диагностики можно пинговать игровые IP. Проверка последовательно: 10.64.0.1 → 192.168.77.1 → 192.168.88.1 → 172.30.88.2.

## 11. Диагностика ошибок по порядку

1. Нет питания — проверь задние FE-входы всех четырёх активных устройств и выходы блока питания.
2. Нет LOCK — проверь две пары коаксиалов, два RF-кабеля, их длины, no shutdown на TX/RX, платы HUB, наведение обеих тарелок и выбранный спутник.
3. Сигнал есть, регистрация не проходит — проверь ID именно модема, одинаковый ключ, имя сети, поляризацию и разные правильные пары частот.
4. LOCK есть, ping до модема не проходит — Ethernet, IP/маска ноутбука, IP LAN модема, no shutdown.
5. До модема ping есть, до HUB нет — адреса Satellite0/0 и ip default-gateway модема. Должна совпасть подсеть 10.254.88.0/24.
6. До HUB ping есть, до интернет-шлюза нет — Ethernet HUB↔шлюз, их LAN IP и обратный маршрут HUB к 192.168.88.0/24.
7. Все ping есть, браузер не открывает — провайдерское поле 172.30.88.2, sat hub, sat internet on, владелец HUB/шлюза, зарегистрированный радиотракт и настоящий интернет Minecraft-сервера.
8. ERR_SOCKS_CONNECTION_FAILED — браузер не смог установить прокси-соединение; это общее сообщение, не доказательство неверного Cisco IP. Сравни простой сайт с нужным, статус внизу окна и доступность сайта на машине сервера. «Остановить» завершает прежнюю браузерную сессию; затем открой приложение заново.

Рецептов Sputnik пока нет. /netlab sputnik kit выдаёт ненастроенное оборудование. /netlab demo sputnik строит отдельный настроенный демонстрационный стенд на свободной загруженной площадке и не заменяет существующие блоки.

## 12. Совместимость и границы модели

Один JAR работает на Windows 10/11 x64 и Linux x64 с полной Java 21. Rinku 3.0.4 скачивает Chromium для текущей ОС при первом запуске; нативные кеши разных ОС не переносятся. На выделенном сервере Chromium и Rinku не нужны.

Штатный GEO-канал: до 25 Мбит/с вниз и 3 Мбит/с вверх на общий ресурс HUB, по 375 мс распространения в каждую сторону плюс очереди. Это учебная модель GEO с фиксированными направлениями, а не настоящая орбитальная и радиочастотная система. Контроллеры скорости NetLab влияют на проводные/спутниковые очереди; очки показывают пакеты пути.

Запуск реального Chromium на Linux проверяется отдельно от модели. Сборка на Java и наличие Windows-библиотек не считаются реальной проверкой браузера на Windows. Проверки проекта не запускают Minecraft, сервер, мир или GameTest.
