# NetLab Sputnik 0.1.3

Один и тот же JAR предназначен для **Windows 10/11 x64 и Linux x64**.
Java 21 и Rinku выбирают нативные библиотеки своей платформы. Sputnik
предварительно загружает AWT текущей Java на обеих системах: `jawt.dll`
на Windows и `libjawt.so` на Linux. Ручное копирование DLL/SO и настройка
`LD_LIBRARY_PATH` для этого не требуются. Нужна полноценная Java 21 с AWT.

Rinku 3.0.4 для NeoForge 1.21.1 устанавливается отдельно на клиент;
при первом запуске он скачивает и проверяет Chromium под ОС и архитектуру.
Нативный кеш от Linux нельзя копировать на Windows и наоборот.
На выделенном сервере браузерные библиотеки не требуются.

Linux проверен отдельным реальным Chromium: HTTPS, изображение и захват PCM.
Выбор и однократность загрузки AWT для Windows и Linux проверяются при сборке.
Нативный Chromium на Windows в текущем окружении не запускался: эту проверку
нельзя считать выполненной по результатам Linux или по сборке Java-кода.

Версия 0.1.1 исправляет Linux-запуск Rinku 3.0.4: библиотека текущей Java
`libjawt.so` загружается до старта JCEF. Это устраняет ошибку
`libjcef.so: libjawt.so: cannot open shared object file` без изменения
системных библиотек, Rinku или переменных окружения Prism. Для Linux нужна
полная Java 21 с AWT, а не headless-only среда.

Аддон для Minecraft 1.21.1 / NeoForge. Требуется NetLab 0.18.3 и, на клиенте,
Rinku 3.0.4. Automation и Mobile для Sputnik не обязательны. Браузер открывает
настоящие сайты через интернет Minecraft-сервера. На выделенном сервере
Chromium и графический интерфейс не запускаются.

## Быстрый старт

С правами оператора, в свободном месте:

```
/netlab demo sputnik
```

Команда проверяет загруженную область 12×8×4 к югу (+Z) и ничего существующего
не заменяет. Строит антенну провайдера, BUC/LNB, шкаф с HUB и интернет-шлюзом,
антенну абонента, VSAT-модем, ноутбук, колонку, питание и кабели. Устанавливает
карты памяти, три платы HUB и уникальную регистрацию модема. Подбирает свободные
подсети. Ключ регистрации в сообщении чата не раскрывается.

ПКМ по ноутбуку → Desktop → **Браузер** → введи `https://example.com` → «Перейти».
Поле шлюза можно оставить пустым, если доступен ровно один интернет-шлюз.
При нескольких шлюзах введи IP из сообщения команды. Нажатие Esc или
«Свернуть / играть» оставляет браузер и музыку в фоне. «Остановить» закрывает
браузер и его соединения. В первой версии одновременно открыт один браузер
на одном компьютере данного игрока; новая ссылка из popup открывается в нём же.

Колонка уже подключена к AudioOut ноутбука и запитана. Запусти аудио на сайте
и сверни браузер. Музыку слышат игроки в радиусе 32 блоков; громкость
уменьшается с расстоянием. ПКМ по колонке — громкость и выключатель.
Обычная громкость Minecraft «Блоки» и основная громкость также учитываются.
В браузере есть собственный переключатель передачи звука на колонку.

`/netlab sputnik kit` выдаёт ненастроенное оборудование, кабели, платы,
карты памяти, книгу и портативный терминал. Предметы находятся во вкладке
**NetLab Sputnik**, платы также — **NetLab модули**. В первой версии
оборудование творческое: рецептов для Sputnik пока нет.

## Состав станции

* **Спутниковый HUB** — устройство в стандартной ячейке шкафа. Внутренние слоты
  `control0`, `tx0`, `rx0` требуют SAT-CONTROL, SAT-TX, SAT-RX. Управление
  абонентами (NMS) выполняет SAT-CONTROL.
* **Интернет-шлюз** — отдельное устройство, устанавливается во вторую ячейку.
  LAN соединён с LAN HUB. Реальный выход — публичные веб-адреса на TCP 80/443.
* **BUC / LNB** — наружный радиоблок: TX-IF/RX-IF к HUB и BUC-TX/LNB-RX
  к большой антенне.
* **Большая антенна** — двухметровый отражатель на опоре с передними RF-портами.
* **Абонентская антенна VSAT** — небольшой отражатель с TX/RX.
* **VSAT-модем** — LAN, Console, TX-IF/RX-IF и внутренний Satellite0/0.
* **Колонка** — AudioIn, питание сзади, громкость/выключатель через ПКМ.

У активных блоков задний вход питания FE. Через блок питания шкафа питаются
HUB (16 FE/тик), интернет-шлюз (8), радиоблок (8), модем (6), колонка (1).
Антенны пассивные. ПК/ноутбук сохраняет прежнее питание от встроенной батареи.

Соединения:

```
HUB TX-IF ── коаксиал TX ── BUC/LNB TX-IF
HUB RX-IF ── коаксиал RX ── BUC/LNB RX-IF
BUC-TX ── радиокабель TX ── большая антенна TX
LNB-RX ── радиокабель RX ── большая антенна RX
Модем TX-IF ── коаксиал TX ── абонентская антенна TX
Модем RX-IF ── коаксиал RX ── абонентская антенна RX
ПК AudioOut ── аудиокабель 3,5 мм ── колонка AudioIn
```

Оба кабеля каждой пары должны приходить в один и тот же блок. Максимальная
длина каждого коаксиала — 64 блока, радиокабеля BUC/LNB → антенна — 8.
Учитывается длина проложенного кабеля с его поворотами. Новые кабели
прокладываются по поверхности и красятся так же, как существующие.

## Наведение и радиоканал

Спутники уже присутствуют в каталоге:

| Спутник | Азимут | Угол места |
|---|---:|---:|
| GEO-1 | 180° | 45° |
| GEO-2 | 90° | 35° |
| GEO-3 | 270° | 55° |

В координатах Minecraft 180° — север. ПКМ по каждой антенне: укажи спутник,
азимут и угол, затем «Навести». На HUB и модеме должен быть выбран тот же
спутник. Проверяется луч на первых 96 блоках от антенны среди загруженных
блоков, а не только вертикальное небо. Башня не требуется. В измерениях без
неба связь недоступна. Рельеф далёкой незагруженной области не проверяется.

Наведение, большая антенна, длина коаксиала и гроза влияют на запас сигнала.
Обычный дождь не отключает сеть. GEO добавляет по 375 мс в каждую сторону,
плюс реальные очереди, сериализация и наземная сеть. Базовый профиль —
25 Мбит/с вниз и 3 Мбит/с вверх. Абоненты одного HUB делят общий радиоканал;
у каждой стороны есть отдельная очередь. Контроллеры скорости NetLab продолжают
действовать. Очки показывают пакеты SAT/... на пути через антенны и радиоблок.

Это учебная GEO-модель: фиксированные направления в плоском мире, ограниченный
каталог и трансляция частот ретранслятором на 2 ГГц. Орбитальная механика,
географические лучи покрытия и движение спутников пока не моделируются.

## Ручная настройка

На всех активных устройствах Console доступна через ноутбук/ПК или
портативный терминал. На выключенном устройстве сначала вставь карту CISCO через физическую панель, затем установи платы и включи питание. Без карты конфигурация временная и при перезагрузке сбрасывается.
Платы HUB устанавливаются при Power OFF. В консоли сетевые команды работают
обычным образом: `enable`, `configure terminal`, `interface GigabitEthernet0/0`,
`ip address IP MASK`, `ip default-gateway IP`, `ip route NET MASK NEXT_HOP`,
`end`, `write memory`.

Пример адресации одного абонента:

| Устройство/интерфейс | IP | Следующий шлюз |
|---|---|---|
| Ноутбук Ethernet | 192.168.77.100/24 | 192.168.77.1 |
| Модем LAN | 192.168.77.1/24 | 10.254.77.1 |
| Модем Satellite0/0 | 10.254.77.2/24 | — |
| HUB Satellite0/0 | 10.254.77.1/24 | — |
| HUB LAN | 172.30.77.1/24 | — |
| Интернет-шлюз LAN | 172.30.77.2/24 | 172.30.77.1 |

На HUB нужен обратный маршрут:
`ip route 192.168.77.0 255.255.255.0 10.254.77.2`.
Отдельные абонентские LAN должны иметь разные подсети. Адреса Satellite0/0
также должны быть уникальными. Внутренние Satellite-порты не предназначены
для физического подключения кабелей.

На HUB в configure terminal:

```
sat network my-provider
sat satellite GEO-1
sat frequencies 14000 12200
sat polarization H
sat subscriber UUID_МОДЕМА СВОЙ_КЛЮЧ
```

UUID модема показывает **его** команда `show sputnik`. Его также можно скопировать кнопкой «Скопировать ID» в панели модема (ПКМ). Придумай ключ 8–64
символа без пробелов. Запись HUB привязана к физической идентичности модема,
поэтому перенос карты на новое устройство не создаёт зарегистрированного абонента.

На модеме в configure terminal:

```
sat network my-provider
sat satellite GEO-1
sat frequencies 14200 12000
sat polarization H
sat key СВОЙ_КЛЮЧ
sat address 10.254.77.2 255.255.255.0
ip default-gateway 10.254.77.1
```

Для GEO-1 по умолчанию HUB передаёт на 14 000 МГц и принимает на 12 200,
абонент передаёт на 14 200 и принимает на 12 000. Прямой и обратный каналы
разные, ретранслятор переводит каждую несущую вниз на 2 000 МГц.

На интернет-шлюзе, принадлежащем тому же игроку, что и HUB:

```
sat hub 172.30.77.1
sat internet on
```

На каждом устройстве: `end`, затем `write memory`. На двух антеннах через ПКМ
выбери GEO-1 / 180 / 45. При OFFLINE проверь обе пары кабелей, FE, три платы HUB,
ключ, UUID, частоты, поляризацию, сеть, наведение и IP-маршруты в обе стороны.
Сам интернет-шлюз включается только при работающем тракте HUB ↔ абонент.

## Команды Sputnik

| Команда | Где и что делает |
|---|---|
| `show sputnik` | ID устройства, LOCK/OFFLINE, несущие, скорость и память |
| `show subscribers` | На HUB: список зарегистрированных UUID; ключи не выводятся |
| `sat panel` | Открывает физическую/измерительную панель |
| `sat network NAME` | Имя сети, одинаковое на HUB и модеме |
| `sat satellite GEO-1` | Выбор спутника; GEO-1/2/3 |
| `sat azimuth N` | Настройка азимута 0..359; у антенн удобнее ПКМ |
| `sat elevation N` | Угол места 5..85; у антенн удобнее ПКМ |
| `sat polarization H` | Поляризация H/V, одинаковая на HUB и модеме |
| `sat frequencies TX RX` | Передающая/приёмная частоты, в МГц; Ku-диапазон |
| `sat rates DOWN UP` | Номинальные лимиты 1..100 и 1..20 Мбит/с; HUB задаёт общую ёмкость |
| `sat subscriber UUID KEY` | На HUB: добавить/сменить ключ физического модема, до 32 записей |
| `sat revoke UUID` | На HUB: немедленно отозвать регистрацию |
| `sat key KEY` | На модеме: ключ, заданный провайдером |
| `sat address IP MASK` | На модеме: IPv4 внутреннего Satellite0/0 |
| `sat internet on/off` | На интернет-шлюзе: разрешить/запретить внешний доступ |
| `sat hub IP` | На интернет-шлюзе: LAN IP своего HUB |
| `sat enabled on/off` | Разрешить/запретить работу спутникового устройства |
| `sat keep-loaded on/off` | Загрузка участка около HUB/шлюза/модема |

Команды `sat ...`, кроме `sat panel`, выполняются в configure terminal.
Это команды NetLab Sputnik, а не команды реального Cisco IOS.

Для работы удалённых станций используется загрузка 3×3 чанков около HUB,
шлюза и модема. По умолчанию включена; ограничение — 16 опорных устройств на
измерение. Кабели и питание станции следует держать в этих пределах.
Радиозона между абонентом и провайдером не загружается. Снятый блок и карта
хранят настройки отдельно от личного браузерного сеанса.

## Браузер и реальный интернет

Chromium работает на клиенте. Его изолированный SOCKS-прокси отправляет
TCP-потоки через сетевые пакеты мода на интернет-шлюз. Внешние сокеты открывает
Minecraft-сервер. Ответы проходят обратный маршрут NetLab до попадания в браузер.
HTTPS проверяет сертификат сайта и остаётся зашифрованным до Chromium.
Отключение кабеля, станции, питания или регистрации закрывает передачу.
Контроллер скорости влияет на настоящие байты, включая музыку.

Внешние сайты видят IP хоста Minecraft-сервера. DNS для SOCKS-подключения
разрешается на интернет-шлюзе. Игровые локальные DNS не заменяют этот внешний
резолвер. Поддерживаются публичные веб-адреса TCP 80/443; локальные и служебные
адреса хоста/сети сервера недоступны через этот шлюз. QUIC и прямой UDP/WebRTC
не используются. VPN NetLab может дополнительно защитить игровой участок.

Личные cookies живут в отдельном контексте Chromium текущего игрока. Они не
записываются в мир, карту, блок и не передаются другим слушателям колонок.
Сеанс сохраняется при закрытии окна браузера, пока игрок в мире и ПК загружен.
При «Остановить», выходе из мира или завершении игры сеанс закрывается.
Смена выбранного ПК закрывает предыдущий браузер. В этой версии нет
многовкладочного интерфейса и сохранения личных cookies между запусками.

HTML5-аудио захватывается из браузера, а не с микрофона, и передаётся слушателям
как PCM 24 кГц mono. Нужны рабочий аудиовыход ОС/JavaSound и громкость «Блоки».
Сайты с DRM, требованиями к аккаунту или конкретным кодекам могут требовать
дополнительной поддержки движка: работа всех музыкальных сервисов не обещается.
При потере интернета уже буферизованная музыка может ещё некоторое время играть.

## Проверки

Minecraft/Prism, игровые серверы, миры и GameTest при разработке не запускались.
Применяются сборка, чистые проверки сети, отдельные проверки реестров/NBT и
HTTPS через production SOCKS-прокси и чистую очередь NetLab. Изолированный
Chromium успешно загрузил HTTPS через этот SOCKS/спутниковый протокол, выдал
кадры OSR и захватил декодированный PCM без прямого звука ОС. Это не заменяет проверку
отрисовки, кликов, установки блоков и звука в самой игре пользователем.

[Comtech BUC/LNB](https://comtech.com/wp-content/uploads/2022/04/ds-DMD1050TS.pdf).
